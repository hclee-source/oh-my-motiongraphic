시험: SQLD
제목 후보:
  - 다 지우고 ROLLBACK 하면 남는 건? DELETE · TRUNCATE · DROP | SQLD
  - DELETE와 TRUNCATE, 다 지우는 건 똑같을까? 제약 조건까지 | SQLD
  - 부모 행을 지우면 자식은? ON DELETE CASCADE와 SET NULL | SQLD
썸네일 문구: 윗줄 ‘다 지우는 세 명령’ / 오해 ‘똑같다?’ / 띠 ‘롤백되는 건 DELETE뿐’
예시 숫자(검수용): 1부 주문 표 5행(주문번호, 금액) 101 120 / 102 80 / 103 250 / 104 60 / 105 300
  DELETE FROM 주문 → 0행 → ROLLBACK → 5행 / DELETE FROM 주문 WHERE 금액 < 100 → 102(80) · 104(60) 삭제 → 3행(101 · 103 · 105)
  TRUNCATE TABLE 주문 → 0행, 구조(열 2개) 남음, 저장 공간 반납 → ROLLBACK → 0행 그대로 / DROP TABLE 주문 → ROLLBACK → 조회하면 오류(ORA-00942, 표 없음)
  오라클 규칙(sqlite로 못 돌림): DELETE는 DML → COMMIT 전 ROLLBACK 가능, 저장 공간 유지. TRUNCATE · DROP은 DDL → 실행 앞뒤 자동 커밋이라 ROLLBACK 불가. TRUNCATE는 WHERE 불가
    DROP은 열 정의와 데이터를 지움(휴지통 때문에 ‘저장 공간도 사라진다’는 말은 쓰지 않음)
  2부 부서(부모) 2행: 10 영업, 20 개발 — 부서번호 PK, 부서명 UNIQUE
  사원(자식) 3행: 1 민수 300 10 / 2 지영 400 20 / 3 현우 350 10 — 사번 PK, 이름 NOT NULL, 급여 CHECK (급여 > 0), 부서번호 FK → 부서(부서번호), 부서번호에는 NOT NULL 없음
  외래키가 참조하는 부모 열은 기본키나 UNIQUE여야 함(여기서는 부서.부서번호 = PK)
  INSERT INTO 사원 VALUES ① (4, 수진, 380, 20) 성공 4행 ② (4, 동훈, 300, 10) PK 중복 실패 ③ (5, NULL, 300, 10) NOT NULL 실패
    ④ (5, 동훈, 0, 10) CHECK 실패 ⑤ (5, 동훈, 300, 30) FK 실패(부서 30 없음) ⑥ (5, 동훈, 300, NULL) 성공(FK 열에 NOT NULL이 없어 NULL 허용) → 성공 2 · 실패 4, 사원 5행
  DELETE FROM 부서 WHERE 부서번호 = 20 → 기본(ON DELETE 절 없음): 자식 지영 · 수진이 있어 실패(ORA-02292), 부서 2행 · 사원 5행 그대로
    ON DELETE CASCADE: 성공, 지영 · 수진도 삭제 → 부서 1행, 사원 3행(민수 · 현우 · 동훈)
    ON DELETE SET NULL: 성공, 지영 · 수진 부서번호가 새로 NULL → 부서 1행, 사원 5행(동훈은 ⑥에서 이미 NULL, 부서번호 NULL은 모두 셋)
  UNIQUE: 부서명 ‘영업’ 한 번 더 → 실패, 부서명 NULL 두 행 → 둘 다 성공(오라클 단일 열 UNIQUE는 NULL 여러 개 허용 — 대본은 ‘NULL 허용’까지만)
  ALTER(SQL Server 차이는 한 줄만): 오라클 ALTER TABLE 사원 MODIFY (급여 NUMBER(10)) / SQL Server ALTER TABLE 사원 ALTER COLUMN 급여 INT

## 1. 다 지우는 건 똑같을까
> 화면: 주문 표 5행 카드 세 장이 나란히 → 카드 위에 각각 DELETE FROM 주문 · TRUNCATE TABLE 주문 · DROP TABLE 주문 → 세 장 모두 행이 사라진다 → 가운데 ‘ROLLBACK 하면?’ → 5행 · 0행 · 표 없음.

1. 주문 표의 다섯 행을 한꺼번에 지우는 명령은 세 가지입니다.
2. WHERE 없이 실행하는 DELETE, 그리고 TRUNCATE와 DROP입니다.
3. 셋 다 실행하고 나면 데이터가 사라지는 건 똑같아 보입니다.
4. 그렇다면 실행한 직후에 ROLLBACK을 하면 어떻게 될까요?
5. DELETE는 다섯 행이 그대로 돌아오고, TRUNCATE는 빈 표만 남고, DROP은 표 자체가 없습니다.
6. 오늘은 이 세 명령의 차이와, 잘못된 데이터를 막아 주는 제약 조건을 정리해 보겠습니다.

## 2. DELETE
> 화면: 왼쪽 SQL 카드 DELETE FROM 주문 → 오른쪽 주문 표 5행이 모두 흐려져 0행, 칩 ‘DML’ → ROLLBACK → 5행 복귀 → 카드에 WHERE 금액 < 100 줄 → 102 · 104(80 · 60) 두 행만 흐려져 3행 → 표 아래 ‘저장 공간 그대로’.

7. 먼저 DELETE는 데이터를 다루는 DML이라서, COMMIT 하기 전이면 ROLLBACK으로 되돌릴 수 있습니다.
8. 다섯 행을 모두 지웠다가 ROLLBACK 하면 다섯 행이 다시 나타납니다.
9. 또 DELETE에는 WHERE를 붙여 지울 행을 고를 수 있습니다.
10. 금액이 100 미만인 행만 지우면 80과 60, 두 행이 빠지고 세 행이 남습니다.
11. 행을 다 지워도 표가 쓰던 저장 공간은 그대로 남아 있습니다.

## 3. TRUNCATE
> 화면: SQL 카드 TRUNCATE TABLE 주문 → 표의 5행이 한 번에 사라지고 머리(주문번호 · 금액)만 남은 빈 표, 0행 → 칩 ‘DDL · 자동 커밋’ → ROLLBACK 줄이 나타나도 0행 그대로 → ‘WHERE ✕’.

12. 다음 TRUNCATE는 행을 한꺼번에 모두 지우고, 열 구성 같은 표의 구조만 남깁니다.
13. 표를 막 만든 상태로 되돌리는 것이라, 저장 공간도 반납합니다.
14. 그런데 TRUNCATE는 DML이 아닌 DDL이고, 오라클에서 DDL은 실행되는 순간 자동으로 커밋됩니다.
15. 그래서 바로 ROLLBACK을 해도 지워진 행은 돌아오지 않고, 0행 그대로입니다.
16. 일부만 골라 지울 수도 없어서, TRUNCATE에는 WHERE를 붙일 수 없습니다.

## 4. DROP
> 화면: SQL 카드 DROP TABLE 주문 → 표 카드가 머리까지 통째로 사라진다 → SELECT * FROM 주문 줄에 ✕ ‘표가 없다’ → 세 칸 비교 카드(DELETE · TRUNCATE · DROP): 분류 DML · DDL · DDL / ROLLBACK ✓ · ✕ · ✕ / 남는 것 표와 저장 공간 · 빈 표 · 없음.

17. 마지막 DROP은 데이터뿐 아니라 표의 구조까지 지웁니다.
18. 열 정의와 데이터가 함께 사라져, 그 표를 조회하면 표가 없다는 오류가 납니다.
19. DROP도 DDL이라 자동으로 커밋되므로, ROLLBACK으로 되살릴 수 없습니다.
20. 세 명령을 나란히 놓으면, ROLLBACK은 DELETE만 됩니다.
21. 남는 것은 DELETE가 표와 저장 공간, TRUNCATE가 빈 표, DROP은 아무것도 없습니다.

## 5. 제약 조건 다섯 가지
> 화면: 부서 표(부서번호 · 부서명) 2행과 사원 표(사번 · 이름 · 급여 · 부서번호) 3행 → 열 머리에 제약 칩이 차례로 붙는다: 부서번호 · 사번 ‘PK’, 부서명 ‘UNIQUE’, 이름 ‘NOT NULL’, 급여 ‘CHECK 급여 > 0’, 사원의 부서번호 ‘FK → 부서’ → 표 이름 옆에 ‘부모’ · ‘자식’ → 부서번호 PK 칩과 FK 칩에 바이올렛 테두리. 아래 설명 카드에 지금 문장의 요점이 한 줄씩(마지막 ‘참조되는 열은 기본키나 UNIQUE’).

22. 이번에는 부서 표와 사원 표로, 잘못된 데이터를 막는 제약 조건 다섯 가지를 보겠습니다.
23. PRIMARY KEY, 곧 기본키는 행 하나하나를 구별하는 열로, UNIQUE와 NOT NULL을 합친 것입니다.
24. 기본키는 표마다 하나만 둘 수 있지만, 여러 열을 묶어 하나의 기본키로 만들 수는 있습니다.
25. UNIQUE는 부서명처럼 같은 값이 두 번 들어가는 것만 막고, NULL은 허용합니다.
26. NOT NULL은 빈칸을 막고, CHECK는 급여가 0보다 커야 한다는 식으로 값의 조건을 정합니다.
27. FOREIGN KEY, 곧 외래키는 사원의 부서번호가 부서 표에 실제로 있는 번호여야 한다는 조건입니다.
28. 이때 참조되는 부서 표를 부모, 참조하는 사원 표를 자식이라고 부릅니다.
29. 부모 쪽에서 참조되는 열은 부서번호처럼 기본키이거나 UNIQUE여야 합니다.

## 6. INSERT 여섯 번
> 화면: 왼쪽 INSERT INTO 사원 VALUES 카드에 값 목록이 한 줄씩 ①(4, '수진', 380, 20) ②(4, '동훈', 300, 10) ③(5, NULL, 300, 10) ④(5, '동훈', 0, 10) ⑤(5, '동훈', 300, 30) ⑥(5, '동훈', 300, NULL) → 줄마다 ✓ 또는 ✕ 칩과 걸린 제약(PK · NOT NULL · CHECK · FK) → 오른쪽 사원 표(이름 아래 회색 글자 ‘부서: 10 영업 · 20 개발’) 행 수 3 → 4 → 5.

30. 사원 표는 민수, 지영, 현우 세 행에서 시작하고, 부서는 10번 영업과 20번 개발입니다.
31. 첫 번째 INSERT로 4번 수진을 20번 부서에 넣으면 성공해서 네 행이 됩니다.
32. 두 번째, 동훈을 같은 4번으로 넣으면 기본키가 겹쳐서 실패합니다.
33. 세 번째, 5번 사원의 이름을 NULL로 넣으면 NOT NULL에 걸려 실패합니다.
34. 네 번째, 급여를 0으로 넣으면 0보다 커야 한다는 CHECK에 걸립니다.
35. 다섯 번째, 부서번호를 30으로 넣으면 부서 표에 30번이 없어서 외래키에 걸립니다.
36. 여섯 번째, 부서번호를 NULL로 넣으면 성공합니다.
37. 이 열에는 NOT NULL을 걸지 않아서, 외래키는 NULL을 받을 수 있기 때문입니다.
38. 여섯 번 가운데 두 번만 성공해서, 사원 표는 다섯 행이 됩니다.

## 7. 부모 행을 지우면
> 화면: 왼쪽 부서 표 2행, 오른쪽 사원 표 5행 → DELETE FROM 부서 WHERE 부서번호 = 20 → 부서 20 행과 사원 지영 · 수진 행에 바이올렛 테두리 → ✕ ‘자식 행이 있어 실패’.

39. 이번에는 거꾸로, 부모인 부서 표에서 20번 개발 부서를 지워 보겠습니다.
40. 사원 표에는 20번 부서에 속한 지영과 수진이 있습니다.
41. 기본 설정에서는 자식 행이 남아 있는 부모 행을 지울 수 없어서, 이 DELETE는 실패합니다.

## 8. ON DELETE CASCADE와 SET NULL
> 화면: 두 표 위 어두운 SQL 카드 한 줄 ‘부서번호 NUMBER REFERENCES 부서(부서번호)’ 끝에 ON DELETE CASCADE가 붙는다 → 부서 20 행과 지영 · 수진 행이 함께 사라져 부서 1행 · 사원 3행 → 표가 앞 상태로 돌아오고 같은 자리 글자가 ON DELETE SET NULL로 바뀐다 → 사원 5행 그대로, 지영 · 수진 부서번호 칸이 새로 NULL(바이올렛 테두리), 원래 NULL이던 동훈 칸은 흐리게, 부서 1행.

42. 외래키를 만들 때 ON DELETE 옵션을 붙이면 이 동작을 바꿀 수 있습니다.
43. ON DELETE CASCADE는 부모 행을 지우면 거기에 딸린 자식 행도 함께 지웁니다.
44. 20번 부서를 지우면 지영과 수진도 사라져, 사원 표는 세 행이 됩니다.
45. ON DELETE SET NULL은 자식 행은 남기고 부서번호만 NULL로 바꿉니다.
46. 그래서 사원 표는 다섯 행 그대로이고, 지영과 수진의 부서번호도 NULL이 됩니다.

## 9. 시험장 체크
> 화면: 체크 카드 세 장이 차례로 → 마지막에 작은 카드 한 줄 ‘열 타입 바꾸기: 오라클 MODIFY · SQL Server ALTER COLUMN’.

47. 시험장에서 챙길 것 세 가지입니다.
48. 첫째, 셋 중 ROLLBACK이 되는 것은 DML인 DELETE뿐이고, TRUNCATE와 DROP은 자동 커밋됩니다.
49. 둘째, 기본키는 UNIQUE와 NOT NULL을 합친 것으로 표마다 하나이고, UNIQUE는 NULL을 허용합니다.
50. 셋째, 외래키 값은 부모에 있는 값이나 NULL이어야 하고, 자식이 있는 부모 행은 기본적으로 못 지웁니다.
51. 덧붙여, 열 타입을 바꿀 때 오라클은 MODIFY를, SQL Server는 ALTER COLUMN을 적습니다.

## 10. 한 줄 정리
> 화면: 두 줄 정리 — ‘DELETE만 되돌리고, TRUNCATE는 빈 표, DROP은 없음’ / ‘외래키는 부모에 있는 값과 NULL만’.

52. 오늘 내용을 한 줄로 정리하면 이렇습니다.
53. DELETE만 되돌릴 수 있고, TRUNCATE는 빈 표를, DROP은 아무것도 남기지 않습니다. 외래키는 부모에 있는 값과 NULL만 받습니다.
