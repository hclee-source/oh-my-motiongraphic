  - 프웨그해셀오, SQL 실행 순서 한 번에 | SQLD
썸네일 문구: 윗줄 ‘SELECT 별칭’ / 오해 ‘WHERE에서?’ / 띠 ‘실행 순서 한 번에’
예시 숫자(검수용): 직원 8행(급여, 만 원) 영업 300 500 400 / 개발 600 200 450 / 인사 350 250
  WHERE 급여 >= 300 → 200·250 빠져 6행 → GROUP BY 부서 3묶음(영업 3, 개발 2, 인사 1) → HAVING COUNT(*) >= 2 → 2묶음
  AVG 영업 (300 + 500 + 400) / 3 = 400, 개발 (600 + 450) / 2 = 525 → ORDER BY 평균 DESC → 개발 525, 영업 400 (2행)
  첫 장 예시: SELECT 이름, 급여 * 12 AS 연봉 … WHERE 연봉 >= 4000 → 오류 / ORDER BY 연봉 → 정상

## 1. 별칭이 통하지 않는 곳
> 화면: SQL 카드 — 급여 * 12 AS 연봉 → ORDER BY 연봉에 ✓ → 같은 별칭을 WHERE에 쓰면 ✕ 오류.

1. 급여에 12를 곱하고 ‘연봉’이라는 별칭을 붙였습니다.
2. 이 별칭으로 ORDER BY를 하면 연봉 순서대로 잘 정렬됩니다.
3. 그런데 같은 별칭을 WHERE에서 쓰면 오류가 납니다.
4. 같은 SQL 안에서 붙인 이름인데, 왜 한쪽에서만 통할까요?
5. 답은 SQL이 처리되는 순서에 있습니다.
6. 오늘은 직원 여덟 명의 표 하나로 그 순서를 한 단계씩 따라가 보겠습니다.

## 2. 쓰는 순서와 처리 순서
> 화면: 여섯 줄 SQL 카드 → 줄 옆에 처리 순번 ⑤①②③④⑥이 차례로 붙는다.

7. SQL을 쓸 때는 SELECT부터 씁니다.
8. 하지만 데이터베이스는 FROM부터 읽습니다.
9. 처리 순서는 FROM, WHERE, GROUP BY, HAVING, SELECT, 그리고 마지막이 ORDER BY입니다.
10. 오늘 따라갈 SQL은 부서별 평균 급여를 구하는 문장입니다.
11. 급여 300 이상인 직원만, 두 명 이상인 부서만, 평균이 높은 순으로 봅니다.

## 3. FROM과 WHERE
> 화면: 왼쪽 SQL 카드에서 지금 처리하는 줄만 밝게, 오른쪽 직원 표 8행 → 급여 200·250 두 행이 흐려지며 6행.

12. 첫 번째 FROM은 직원 표 여덟 행을 그대로 가져옵니다.
13. 두 번째 WHERE는 행을 하나씩 보며 조건에 맞지 않는 행을 버립니다.
14. 급여가 300 미만인 두 명이 빠져서 여섯 행이 남습니다.
15. WHERE는 아직 묶기 전이라, 한 행 한 행만 볼 수 있습니다.

## 4. GROUP BY
> 화면: 남은 6행이 부서별 세 묶음(영업 3, 개발 2, 인사 1)으로 모인다.

16. 세 번째 GROUP BY는 남은 여섯 행을 부서별로 묶습니다.
17. 영업 세 명, 개발 두 명, 인사 한 명, 세 묶음이 됩니다.
18. 이제부터는 행이 아니라 묶음 단위로 계산합니다.
19. COUNT나 AVG 같은 집계 함수가 여기서부터 의미를 갖습니다.

## 5. HAVING
> 화면: 인사 묶음(1명)이 흐려진다 → ‘WHERE는 행을, HAVING은 묶음을’.

20. 네 번째 HAVING은 묶음을 거르는 조건입니다.
21. 두 명 이상인 부서만 남기라고 했으니, WHERE를 거치고 한 명만 남은 인사 부서가 빠집니다.
22. WHERE가 행을 거른다면, HAVING은 묶음을 거릅니다.

## 6. SELECT와 ORDER BY
> 화면: 묶음마다 평균 400, 525 → 별칭 ‘평균’이 붙는 순간 → 정렬해 결과 2행.

23. 다섯 번째에야 SELECT가 실행됩니다.
24. 영업은 300, 500, 400의 평균 400, 개발은 600과 450의 평균 525입니다.
25. 별칭 ‘평균’도 바로 이 순간에 생깁니다.
26. 마지막 ORDER BY가 평균이 높은 순으로 정렬해, 개발 525, 영업 400이 결과입니다.
27. 여덟 행으로 시작해 두 행이 남았습니다.

## 7. 별칭과 집계 함수
> 화면: 처리 순서 여섯 칸 — WHERE(2)와 SELECT(5) 사이 화살표 → ‘별칭은 아직 없다’ → WHERE에 COUNT ✕, HAVING에 ✓.

28. 이제 처음 질문으로 돌아가 보겠습니다.
29. WHERE는 두 번째, SELECT는 다섯 번째에 처리됩니다.
30. WHERE가 실행될 때는 ‘연봉’이라는 별칭이 아직 없으니 오류가 납니다.
31. ORDER BY는 SELECT보다 뒤라서 별칭을 쓸 수 있습니다.
32. 같은 원리로 WHERE에는 COUNT나 AVG 같은 집계 함수를 쓸 수 없습니다.
33. 묶음은 GROUP BY에서 생기는데, WHERE는 그보다 먼저이기 때문입니다.
34. 묶음에 대한 조건은 HAVING에 적어야 합니다.

## 8. 시험장 체크
> 화면: 체크 카드 세 장이 차례로 → 마지막에 작은 카드 ‘GROUP BY에 없는 열은 SELECT에 그냥 못 쓴다’.

35. 시험장에서 챙길 것 세 가지입니다.
36. 첫째, 처리 순서는 FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY입니다.
37. 둘째, SELECT에서 붙인 별칭은 ORDER BY에서만 쓸 수 있고, WHERE, GROUP BY, HAVING에서는 쓸 수 없습니다.
38. 셋째, 집계 함수 조건은 WHERE가 아니라 HAVING에 적습니다.
39. 덧붙여, GROUP BY를 쓰면 GROUP BY에 없는 열은 집계 함수로 감싸지 않고는 SELECT에 쓸 수 없습니다.

## 9. 한 줄 정리
> 화면: 여섯 칸 순서 + 앞 글자 ‘프 · 웨 · 그 · 해 · 셀 · 오’.

40. 오늘 내용을 한 줄로 정리하면 이렇습니다.
41. FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY. 앞 글자만 따면, 프, 웨, 그, 해, 셀, 오입니다.
