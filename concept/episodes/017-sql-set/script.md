썸네일 문구: 윗줄 ‘4행 UNION 3행’ / 오해 ‘7행?’ / 띠 ‘집합 연산자 행 수 세기’
예시 숫자(검수용): 봄응모 4행 — 민수, 지영, 지영, 현우(지영 두 번 응모) / 여름응모 3행 — 현우, 수진, 수진(수진 두 번 응모) / 두 표 모두 이름 열 하나 / 양쪽에 있는 이름은 현우
  SQL: SELECT 이름 FROM 봄응모 [연산자] SELECT 이름 FROM 여름응모
  UNION ALL 4 + 3 = 7(지영 · 현우 · 수진 모두 두 번씩) / UNION 7 − 3 = 4(민수 · 지영 · 현우 · 수진; 빠지는 셋 = 봄 안의 지영 하나, 양쪽의 현우 하나, 여름 안의 수진 하나)
  INTERSECT 1(현우) — 가정: 봄에 현우가 두 번이어도 1 / 봄응모 MINUS 여름응모 2(민수 · 지영, 지영은 한 번) / 여름응모 MINUS 봄응모 1(수진, 한 번)
  위아래를 바꿔도 같은 행: UNION ALL · UNION · INTERSECT / MINUS만 2 → 1로 달라짐
  규칙(오라클): 열 개수 같아야 함(SELECT 이름, '봄' FROM 봄응모 UNION SELECT 이름 FROM 여름응모 → 2열 · 1열이라 오류), 같은 자리 열은 자료형이 맞아야 함(문자 vs 숫자 → ORA-01790)
  결과 열 이름 = 첫 번째 SELECT(이름 AS 응모자 … UNION … 이름 AS 고객 → 열 이름 ‘응모자’)
  ORDER BY는 맨 마지막 SELECT 뒤에 한 번(첫 SELECT 뒤에 적으면 오류 ORA-00933), 기준은 첫 SELECT의 열 이름 — 별칭을 붙였으면 별칭(원래 열 이름은 ORA-00904) — 또는 열 순서 번호, 전체 결과를 정렬
  UNION은 중복을 지우는 작업이 더 있어 UNION ALL보다 무거움, UNION 결과의 순서는 보장되지 않음(필요하면 ORDER BY)
  NULL: 집합 연산자는 NULL끼리 같은 값으로 봄(SELECT NULL UNION SELECT NULL → 1행, INTERSECT → 1행, MINUS → 0행; WHERE NULL = NULL은 0행)
  SQL Server는 MINUS 대신 EXCEPT
  검증: verify_examples.py(sqlite3로 UNION ALL · UNION · INTERSECT · EXCEPT 실행, 쇼츠 숫자 포함, 모두 통과)

## 1. 4행과 3행을 합치면
> 화면: 봄응모 표 카드(4행)와 여름응모 표 카드(3행)가 양옆에 → 가운데 SQL 카드 ‘SELECT 이름 FROM 봄응모 / UNION / SELECT 이름 FROM 여름응모’ → 결과 칸 ‘? 행’ → ‘7행’에 ✕ → ‘4행’.

1. 봄 이벤트 응모 기록이 4행, 여름 이벤트 응모 기록이 3행 있습니다.
2. 이 두 결과를 UNION으로 합치면 몇 행이 나올까요?
3. 4 더하기 3, 7행이라고 답하면 틀립니다.
4. 정답은 4행입니다.
5. 오늘은 이 두 표로 집합 연산자 네 개의 결과 행 수를 직접 세어 보겠습니다.

## 2. 두 표
> 화면: 왼쪽 봄응모 표 4행(민수 · 지영 · 지영 · 현우), 오른쪽 여름응모 표 3행(현우 · 수진 · 수진), 둘 다 ‘이름’ 열 하나 → 지영 두 행, 수진 두 행에 차례로 표시 → 양쪽 현우를 선으로 잇기 → 아래에 SQL 틀 ‘SELECT … / 연산자 / SELECT …’.

6. 왼쪽은 봄 응모 표, 오른쪽은 여름 응모 표이고, 둘 다 이름 열 하나뿐입니다.
7. 봄에는 민수, 지영, 현우가 응모했는데, 지영이 두 번 응모해서 4행입니다.
8. 여름에는 현우와 수진이 응모했고, 수진이 두 번 응모해서 3행입니다.
9. 현우는 봄과 여름에 모두 응모했습니다.
10. 집합 연산자는 두 SELECT 문 사이에 적고, 두 결과의 행을 위아래로 합치거나 비교합니다.

## 3. UNION ALL
> 화면: 왼쪽 SQL 카드 가운데 줄 ‘UNION ALL’만 밝게 → 오른쪽 결과 표에 봄 4행이 들어오고 그 아래로 여름 3행이 그대로 쌓여 7행(표 머리 ‘7행’) → 지영 · 현우 · 수진 두 번씩에 표시.

11. 먼저 UNION ALL입니다.
12. 첫 번째 SELECT의 결과 밑에 두 번째 SELECT의 결과를 그대로 이어 붙입니다.
13. 중복을 전혀 지우지 않으니, 4 더하기 3, 7행입니다.
14. 지영, 현우, 수진이 모두 두 번씩 나옵니다.

## 4. UNION
> 화면: 가운데 줄이 ‘UNION’으로 바뀜 → 7행 중 두 번째 현우가 흐려짐 → 두 번째 지영, 두 번째 수진도 흐려짐 → 남은 4행(민수 · 지영 · 현우 · 수진), 표 머리 ‘4행’ → 아래 식 ‘7 − 3 = 4’.

15. 이번에는 ALL을 뺀 UNION입니다.
16. UNION은 결과를 합친 다음, 중복된 행을 지워 한 번씩만 남깁니다.
17. 봄과 여름 양쪽에 있는 현우는 하나만 남습니다.
18. 여기서 놓치기 쉬운 것이 한 표 안의 중복입니다.
19. 봄 표 안에서 두 번 나온 지영, 여름 표 안에서 두 번 나온 수진도 하나씩 지워집니다.
20. 7행에서 세 행이 빠져, 민수, 지영, 현우, 수진, 이렇게 4행이 남습니다.
21. 한 번이라도 응모한 사람의 명단이 된 셈입니다.

## 5. INTERSECT
> 화면: 가운데 줄 ‘INTERSECT’ → 두 표에서 현우만 밝게, 나머지는 흐리게 → 결과 표 1행(현우), 표 머리 ‘1행’ → 작은 메모 ‘봄에 현우가 두 번이어도 1행’.

22. INTERSECT는 두 결과에 모두 있는 행만 남깁니다.
23. 봄과 여름에 모두 응모한 사람은 현우뿐이라 1행입니다.
24. INTERSECT도 중복을 지우기 때문에, 현우가 봄에 두 번 응모했더라도 결과는 1행입니다.

## 6. MINUS
> 화면: 가운데 줄 ‘MINUS’ → 봄 표 4행에서 현우가 지워지고 지영 두 행이 하나로 → 결과 2행(민수 · 지영) → SQL 카드 위아래가 바뀐 ‘여름응모 MINUS 봄응모’ → 여름 표 3행에서 현우가 지워지고 수진 두 행이 하나로 → 결과 1행(수진) → ‘2행’ · ‘1행’ 나란히, 그 아래 한 줄 ‘SQL Server는 EXCEPT’.

25. MINUS는 위 결과에서 아래 결과에 있는 행을 뺍니다.
26. 봄응모 MINUS 여름응모는 봄에만 응모한 사람을 구합니다.
27. 봄의 4행에서 여름에도 있는 현우를 빼면 민수와 지영이 남습니다.
28. 지영은 두 번 응모했지만, MINUS도 중복을 지우므로 한 번만 나와서 2행입니다.
29. 이번에는 위아래를 바꿔 여름응모 MINUS 봄응모입니다.
30. 여름의 3행에서 현우를 빼면 수진만 남고, 역시 한 번만 나와 1행입니다.
31. 같은 두 표인데 순서를 바꾸자 2행이 1행으로 바뀌었습니다.
32. UNION이나 INTERSECT는 위아래를 바꿔도 나오는 행이 같지만, MINUS는 순서가 중요합니다.
33. SQL Server에서는 MINUS 대신 EXCEPT라고 적습니다.

## 7. 네 결과 비교
> 화면: 네 줄 카드 — UNION ALL 7행 · UNION 4행 · INTERSECT 1행 · MINUS 2행(거꾸로 1행) → UNION ALL 줄 옆 ‘중복 남김’, 나머지 세 줄 옆 ‘중복 지움’.

34. UNION ALL 7행, UNION 4행, INTERSECT 1행, MINUS 2행, 거꾸로 하면 1행입니다.
35. 중복을 그대로 남기는 것은 UNION ALL 하나뿐이고, 나머지 셋은 모두 중복을 지웁니다.

## 8. 열 개수와 열 이름
> 화면: SQL 카드 — 위 ‘SELECT 이름, '봄' FROM 봄응모’ / 아래 ‘SELECT 이름 FROM 여름응모’ → 열 수 2 · 1 표시와 ✕ → 고친 SQL 카드: 위 ‘이름 AS 응모자’ / 아래 ‘이름 AS 고객’ → 결과 표 머리에 ‘응모자’(‘고객’은 흐리게).

36. 집합 연산자에는 지켜야 할 규칙이 있습니다.
37. 위아래 SELECT의 열 개수가 같아야 하고, 같은 자리의 열끼리는 자료형이 맞아야 합니다.
38. 위에서는 이름에 ‘봄’이라는 표시 열을 더해 두 열, 아래에서는 이름 하나만 고르면 오류가 납니다.
39. 결과의 열 이름은 첫 번째 SELECT를 따릅니다.
40. 위에 응모자, 아래에 고객이라는 별칭을 붙이면, 결과 열 이름은 응모자가 됩니다.

## 9. UNION ALL이 가벼운 이유
> 화면: 두 줄 비교 — UNION = 합치기 → 중복 찾아 지우기(한 단계 더) / UNION ALL = 합치기만 → ‘중복이 없거나 상관없으면 UNION ALL’ → ‘UNION 결과 순서는 보장 ✕’.

41. UNION은 합친 결과에서 중복을 찾아 지우는 작업을 한 번 더 합니다.
42. 그래서 중복이 생길 수 없거나 중복이 있어도 괜찮다면, UNION ALL이 더 가볍습니다.
43. 중복을 지우는 과정에서 결과가 정렬된 것처럼 보일 때도 있지만, 순서는 보장되지 않습니다.

## 10. ORDER BY는 맨 끝에
> 화면: SQL 카드 — 첫 SELECT 바로 뒤의 ‘ORDER BY’ ✕ → 맨 끝 줄 ‘ORDER BY 응모자’ ✓ → 같은 자리 ‘ORDER BY 1’ ✓ → 결과 표 4행 전체가 정렬.

44. 순서가 필요하면 ORDER BY를 적는데, 맨 마지막 SELECT 뒤에 한 번만 적을 수 있습니다.
45. 첫 번째 SELECT 뒤에 ORDER BY를 적으면 오류가 납니다.
46. 정렬 기준에는 첫 번째 SELECT의 열 이름을 적는데, 별칭을 붙였다면 별칭을, 또는 열의 순서 번호를 적습니다.
47. 맨 끝의 ORDER BY는 합쳐진 전체 결과를 정렬합니다.

## 11. 시험장 체크
> 화면: 체크 카드 세 장이 차례로 → 마지막에 작은 카드 ‘NULL끼리도 같은 값으로 본다’.

48. 시험장에서 챙길 것 세 가지입니다.
49. 첫째, 중복을 남기는 것은 UNION ALL뿐이고, 나머지 셋은 한 표 안의 중복까지 지웁니다.
50. 둘째, MINUS는 위아래 순서를 바꾸면 결과가 달라집니다.
51. 셋째, 열 이름은 첫 번째 SELECT를 따르고, ORDER BY는 맨 끝에 한 번만 적습니다.
52. 덧붙여, 등호 비교와 달리 집합 연산자는 NULL끼리도 같은 값으로 봅니다.

## 12. 한 줄 정리
> 화면: 네 줄 정리 — 모두 합치기 UNION ALL / 중복 없이 합치기 UNION / 겹치는 것만 INTERSECT / 위에만 있는 것 MINUS.

53. 오늘 내용을 한 줄로 정리하면 이렇습니다.
54. 모두 합치면 UNION ALL, 중복 없이 합치면 UNION, 겹치는 것만 INTERSECT, 위에만 있는 것은 MINUS입니다.
