썸네일 문구: 윗줄 ‘ROWNUM으로 자르면’ / 오해 ‘상위 3명?’ / 띠 ‘번호는 정렬 전에 붙는다’
예시 숫자(검수용): 직원 7행(이름 급여, 만 원), 저장된 순서 지영 300, 민수 400, 수진 250, 현우 500, 예린 400, 동훈 450, 태호 350
  ORDER BY가 없으면 읽는 순서는 보장되지 않음 → 대본은 ‘저장된 순서대로 읽힌다고 가정’(2장에서 그렇게 말함)
  급여 내림차순: 현우 500, 동훈 450, 민수 400 · 예린 400(공동 3등, 둘의 앞뒤는 정해지지 않음), 태호 350, 지영 300, 수진 250
  ROWNUM 규칙(오라클): 행을 읽을 때 지금 차례의 번호(1부터)를 붙여 보고, WHERE를 통과하면 번호 확정·다음 번호로, 버려지면 번호 그대로. WHERE 단계라 ORDER BY보다 먼저
  ① WHERE ROWNUM <= 3 ORDER BY 급여 DESC: 지영 1 · 민수 2 · 수진 3 통과, 현우 · 예린 · 동훈 · 태호는 받을 번호가 4라 탈락 → 3행을 정렬 → 민수 400, 지영 300, 수진 250 (현우 500 빠짐)
  ② ROWNUM = 1 → 1행(지영) / ROWNUM = 2 → 0행(일곱 행 모두 1을 받고 탈락) / ROWNUM > 1 → 0행 / ROWNUM >= 4 → 0행
  ③ SELECT * FROM (SELECT 이름, 급여 FROM 직원 ORDER BY 급여 DESC) WHERE ROWNUM <= 3 → 현우 500, 동훈 450, 400 한 명(민수 또는 예린) = 3행
  ④ 구간: SELECT * FROM (SELECT ROWNUM AS 순번, 이름, 급여 FROM (SELECT 이름, 급여 FROM 직원 ORDER BY 급여 DESC)) WHERE 순번 BETWEEN 4 AND 6 → 급여 400(③에서 빠진 쪽), 350, 300 = 3행
  ⑤ (오라클 12c부터) ORDER BY 급여 DESC FETCH FIRST 3 ROWS ONLY → ③과 같은 3행 / FETCH FIRST 3 ROWS WITH TIES → 500, 450, 400, 400 = 4행(마지막 행 400과 같은 값까지) / OFFSET 3 ROWS FETCH NEXT 3 ROWS ONLY → 400, 350, 300 = 3행
  ⑥ SQL Server: SELECT TOP(3) 이름, 급여 FROM 직원 ORDER BY 급여 DESC → 정렬한 뒤 자르므로 ③과 같은 3행 / TOP(3) WITH TIES → 4행

## 1. 상위 3명을 뽑았는데
> 화면: SQL 카드 4줄(SELECT 이름, 급여 / FROM 직원 / WHERE ROWNUM <= 3 / ORDER BY 급여 DESC) → 결과 표 ‘3행’ 민수 400 · 지영 300 · 수진 250 → 표 아래 칩 ‘급여 500인 직원은?’ → 칩 ‘✕ 상위 3명이 아니다’, 결과 표는 흐리게.

1. 급여가 가장 높은 직원 세 명을 뽑으려고 이런 SQL을 적었습니다.
2. WHERE에서 ROWNUM이 3 이하인 행만 남기고, ORDER BY로 급여가 높은 순으로 정렬했습니다.
3. 결과는 400, 300, 250을 받는 세 명입니다.
4. 그런데 직원 표에는 급여가 500인 직원이 있습니다.
5. 상위 3명을 뽑았는데, 왜 1등이 빠졌을까요?
6. 오늘은 직원 일곱 명의 표로 ROWNUM이 붙는 순간을 따라가 보겠습니다.

## 2. 직원 표와 읽는 순서
> 화면: 직원 표 7행(이름 · 급여)을 저장된 순서대로 — 지영 300 · 민수 400 · 수진 250 · 현우 500 · 예린 400 · 동훈 450 · 태호 350 → 앞 세 행, 이어서 넷째 행 현우가 밝아짐 → 왼쪽 메모 카드 ‘ORDER BY가 없으면 읽는 순서는 보장되지 않음 / 저장된 순서대로 읽는다고 가정’ → 행 옆에 급여 순위 현우 ‘1등’ · 동훈 ‘2등’ · 민수 · 예린 ‘공동 3등’.

7. 저장된 순서로 보면 지영 300, 민수 400, 수진 250이 앞의 세 명이고, 현우 500은 네 번째입니다.
8. ORDER BY가 없으면 행을 읽는 순서는 정해져 있지 않지만, 여기서는 저장된 순서대로 읽힌다고 가정합니다.
9. 급여 순으로는 현우 500, 동훈 450, 그리고 400을 받는 민수와 예린이 공동 3등입니다.

## 3. ROWNUM이 붙는 순간
> 화면: 왼쪽 SQL 카드 WHERE 줄만 밝게 → 오른쪽 표(저장된 순서)에 ROWNUM 칸이 생기고 위에서부터 지영 1 · 민수 2 · 수진 3이 차례로 붙음 → 현우 행에 4가 붙었다가 ✕ → 아래 예린 · 동훈 · 태호도 4 ✕ → 표 머리 ‘3행’.

10. ROWNUM은 오라클이 조회하면서 행에 1부터 차례로 붙이는 번호입니다.
11. 행을 하나 읽을 때마다 지금 차례의 번호를 붙여 보고, WHERE 조건을 통과해야 다음 번호로 넘어갑니다.
12. WHERE 단계에서 붙으니, 맨 마지막인 ORDER BY보다 한참 먼저입니다.
13. 첫 행 지영이 1번, 민수가 2번, 수진이 3번을 받고 모두 통과합니다.
14. 다음 행 현우는 4번을 받는데, 3 이하가 아니라서 버려집니다.
15. 뒤의 행들도 계속 4번이라 버려지고, 처음 읽은 세 행만 남습니다.

## 4. 정렬은 그다음
> 화면: 남은 3행(지영 300 · 민수 400 · 수진 250) → SQL 카드 ORDER BY 줄 밝게 → 민수 400 · 지영 300 · 수진 250으로 자리 바꿈 → 옆에 빠진 현우 500 · 동훈 450은 흐린 칩 → 칩 ‘먼저 읽힌 세 명을 정렬’.

16. ORDER BY는 이미 세 행만 남은 뒤에 정렬하니, 그 세 행 안에서 순서만 바뀝니다.
17. 그래서 결과는 민수 400, 지영 300, 수진 250입니다.
18. 상위 3명이 아니라 먼저 읽힌 세 명을 정렬한 것입니다.
19. 이것이 첫 번째 함정입니다.

## 5. ROWNUM = 2는 0행
> 화면: SQL 카드 WHERE ROWNUM = 1 → 결과 지영 1행 ✓ → 조건이 ROWNUM = 2로 바뀜 → 표 위에서부터 지영에 1 ✕, 민수에도 다시 1 ✕ … 일곱 행 모두 1 ✕ → 결과 ‘0행’ → 아래 칩 ‘ROWNUM > 1 → 0행’.

20. 두 번째 함정은 ROWNUM으로 특정 번호를 찾을 때 나옵니다.
21. ROWNUM = 1이라고 적으면 첫 행인 지영 한 명이 잘 나옵니다.
22. 그런데 두 번째 행을 보려고 ROWNUM = 2라고 적으면, 결과는 0행입니다.
23. 첫 행 지영은 1번을 받는데, 2가 아니라서 버려집니다.
24. 행이 버려지면 번호가 넘어가지 않으니, 다음 행 민수도 다시 1번을 받고 버려집니다.
25. 그렇게 일곱 행이 모두 버려져, 2번은 끝내 생기지 않습니다.
26. 같은 이유로 ROWNUM이 1보다 크다는 조건도 0행입니다.

## 6. 정렬 먼저, 번호는 바깥에서
> 화면: SQL 카드 — 바깥 SELECT * FROM ( … ) WHERE ROWNUM <= 3, 괄호 안 SELECT 이름, 급여 FROM 직원 ORDER BY 급여 DESC(안쪽 줄이 먼저 밝게) → 칩 ‘인라인 뷰’ → 표가 급여 순 7행으로 정렬 → ROWNUM 1 · 2 · 3 → 현우 500 · 동훈 450 · 400 한 명 ✓ ‘3행’ → 민수 · 예린 두 행에 ‘누가 3번일지 정해지지 않음’.

27. 상위 3명을 뽑으려면, 정렬을 먼저 끝내고 그다음에 번호를 붙이면 됩니다.
28. 정렬하는 SELECT를 FROM 절 괄호 안에 넣고, 바깥 SELECT의 WHERE에서 ROWNUM으로 자릅니다.
29. 괄호 안의 SELECT를 인라인 뷰라고 하고, 안쪽에서 먼저 정렬한 뒤 바깥에서 거르는 것이 핵심입니다.
30. 안쪽에서 일곱 행이 급여 순으로 나오고, 바깥에서 그 순서대로 1번, 2번, 3번이 붙습니다.
31. 결과는 현우 500, 동훈 450, 그리고 400을 받는 한 명입니다.
32. 민수와 예린은 둘 다 400이라, 누가 3번이 될지는 정해져 있지 않습니다.

## 7. 중간 구간 자르기
> 화면: 칩 ‘ROWNUM >= 4 → 0행’ ✕ → 세 겹 SQL 카드 — 가장 안쪽 ORDER BY 급여 DESC / 가운데 SELECT ROWNUM AS 순번, 이름, 급여 / 바깥 WHERE 순번 BETWEEN 4 AND 6(가운데 줄, 이어서 바깥 줄이 밝게) → 결과 표 ‘3행’ 순번 4 · 5 · 6 = 400 · 350 · 300.

33. 네 번째부터 여섯 번째까지를 뽑을 때, ROWNUM이 4 이상이라고 바로 적으면 앞에서 본 것처럼 0행입니다.
34. 그래서 정렬한 인라인 뷰 바깥에서 ROWNUM에 순번이라는 별칭을 붙여 둡니다.
35. 그리고 한 겹 더 바깥에서 순번으로 거르면, 순번 4부터 6까지인 400, 350, 300이 나옵니다.

## 8. FETCH FIRST와 WITH TIES
> 화면: SQL 카드 SELECT 이름, 급여 / FROM 직원 / ORDER BY 급여 DESC / FETCH FIRST 3 ROWS ONLY(작은 칩 ‘오라클 12c부터’) → 결과 3행(400 한 명) → ONLY가 WITH TIES로 바뀌며 민수 · 예린 두 행 모두 → ‘4행’ → ORDER BY 줄은 그대로 두고 마지막 줄만 OFFSET 3 ROWS FETCH NEXT 3 ROWS ONLY로 → 400 · 350 · 300 ‘3행’.

36. 오라클 12c부터는 인라인 뷰 없이 한 번에 자를 수도 있습니다.
37. ORDER BY 뒤에 FETCH FIRST 3 ROWS ONLY를 적으면, 정렬된 결과에서 앞의 세 행만 가져옵니다.
38. 이 구문은 ORDER BY 다음에 처리되므로, 같은 SELECT 안에 있어도 정렬이 먼저입니다.
39. 결과는 인라인 뷰와 같은 3행이고, 400인 두 명 중 한 명만 들어갑니다.
40. ONLY 대신 WITH TIES를 적으면, 마지막 행과 급여가 같은 행까지 함께 가져옵니다.
41. 민수와 예린이 모두 들어가서, 결과는 3행이 아니라 4행입니다.
42. 동점은 ORDER BY 기준으로 가리니, WITH TIES는 ORDER BY와 함께 적습니다.
43. 중간 구간은 OFFSET으로 건너뜁니다.
44. OFFSET 3 ROWS로 세 행을 건너뛰고, FETCH NEXT 3 ROWS ONLY로 400, 350, 300을 가져옵니다.

## 9. SQL Server의 TOP
> 화면: SQL 카드 SELECT TOP(3) 이름, 급여 / FROM 직원 / ORDER BY 급여 DESC → 칩 ‘정렬한 뒤에 자른다’ → 아래 줄 TOP(3) WITH TIES(‘동점까지’).

45. SQL Server에서는 SELECT 바로 뒤에 TOP(3)을 적습니다.
46. TOP은 정렬한 뒤에 자르니 ORDER BY와 함께 적으면 되고, 동점까지 넣으려면 WITH TIES를 붙입니다.

## 10. 시험장 체크
> 화면: 체크 카드 세 장이 차례로 → 마지막에 작은 카드 ‘WITH TIES는 적은 개수보다 많이 나올 수 있다’.

47. 시험장에서 챙길 것 세 가지입니다.
48. 첫째, WHERE에서 ROWNUM으로 자르고 같은 SELECT에서 ORDER BY를 적으면, 먼저 읽힌 행을 자른 뒤에 정렬합니다.
49. 둘째, ROWNUM이 1과 같거나 3 이하인 조건은 되지만, 2와 같거나 1보다 크다는 조건은 0행입니다.
50. 셋째, 상위 몇 개는 정렬한 인라인 뷰 바깥에서 ROWNUM으로 자르거나, ORDER BY 뒤에 FETCH FIRST를 적습니다.
51. 덧붙여, WITH TIES는 마지막 행과 동점인 행까지 넣어서, 적은 개수보다 많이 나올 수 있습니다.

## 11. 한 줄 정리
> 화면: 한 줄 정리 ‘ROWNUM은 정렬 전에 붙는 번호’ → ‘정렬은 안쪽에서, 번호는 바깥에서’.

52. 오늘 내용을 한 줄로 정리하면 이렇습니다.
53. ROWNUM은 정렬하기 전에 붙는 번호이니, 정렬은 안쪽에서 먼저 하고 번호는 바깥에서 붙입니다.
