시험: SQLD
제목 후보:
  - 부서는 2개인데 PIVOT 결과는 3행? PIVOT · UNPIVOT | SQLD
  - PIVOT은 남은 열로 묶인다, 인라인 뷰가 필요한 이유 | SQLD

썸네일 문구: 윗줄 ‘PIVOT 결과 행 수’ / 오해 ‘부서 수?’ / 띠 ‘남은 열로 묶이는 PIVOT’
예시 숫자(검수용): 실적 7행(부서 · 분기 · 매출 · 담당자) — 영업 1 90 민수 / 영업 1 60 지영 / 영업 2 120 민수 / 영업 3 110 민수 / 영업 4 130 민수 / 개발 1 70 현우 / 개발 3 80 현우
  첫 장·5장 SELECT * FROM 실적 PIVOT (SUM(매출) FOR 분기 IN (1 AS Q1, 2 AS Q2, 3 AS Q3)) → 남은 열 부서 · 담당자로 묶여 3행: 영업 민수 90 · 120 · 110 / 영업 지영 60 · NULL · NULL / 개발 현우 70 · NULL · 80
  3·4장 SELECT * FROM (SELECT 부서, 분기, 매출 FROM 실적) PIVOT (같은 괄호) → 남은 열 부서로 묶여 2행: 영업 150(90 + 60) · 120 · 110 / 개발 70 · NULL · 80, 영업 4분기 130은 IN 목록에 없어 빠짐 → 7행 → 2행
  6장 SELECT 부서, SUM(CASE WHEN 분기 = 1 THEN 매출 END) AS Q1, (Q2 · Q3 같은 꼴) FROM 실적 GROUP BY 부서 → 4장과 같은 2행(담당자 열이 있어도 GROUP BY 부서라 갈라지지 않음)
  7장 4장 결과 2행을 표 분기실적(부서, Q1, Q2, Q3)으로 → SELECT * FROM 분기실적 UNPIVOT (매출 FOR 분기 IN (Q1, Q2, Q3)) → 칸 2 × 3 = 6개, NULL 1개(개발 Q2) 빠져 5행: 영업 Q1 150 · 영업 Q2 120 · 영업 Q3 110 · 개발 Q1 70 · 개발 Q3 80(분기 칸에는 원래 열 이름 Q1 · Q2 · Q3이 문자로) / UNPIVOT INCLUDE NULLS (…) → 6행 / 원래 7행으로는 안 돌아옴(150은 90 · 60으로 안 나뉨, 4분기 130 없음)
  오라클 규칙(검수용): PIVOT 절은 집계 함수가 반드시 필요 / GROUP BY를 적지 않고 PIVOT 절에 나오지 않은 모든 열로 암묵적으로 묶음(오라클 문서: implicit GROUP BY based on all the columns not referred to in the pivot_clause) / IN 목록 값만 열이 됨, 데이터 없는 칸은 SUM 결과 NULL / UNPIVOT 기본은 EXCLUDE NULLS, INCLUDE NULLS는 UNPIVOT 바로 뒤에 적음 / SQL Server는 IN 목록에 별칭(AS) 없이 IN ([1], [2], [3])처럼 대괄호(그 값이 곧 열 이름)

## 1. 부서는 둘, 결과는 세 줄
> 화면: SQL 카드 ‘SELECT * FROM 실적 PIVOT (SUM(매출) FOR 분기 IN (1 AS Q1, 2 AS Q2, 3 AS Q3))’ → 칩 ‘부서 2개 → 2행?’ → 결과 표 3행(부서 · 담당자 · Q1 · Q2 · Q3)이 나오고 영업 두 줄이 밝게.

1. 부서별 분기 매출을 한 줄씩 보려고 PIVOT을 썼습니다.
2. 부서는 영업과 개발 두 개뿐이니, 결과도 2행이 나올 것 같습니다.
3. 그런데 실제 결과는 3행이고, 영업이 두 줄로 갈라져 있습니다.
4. SQL에 오류도 없는데, 왜 이렇게 나왔을까요?
5. 답은 PIVOT이 행을 묶는 방식에 있습니다.
6. 오늘은 실적 표 하나로 PIVOT과 UNPIVOT을 한 단계씩 따라가 보겠습니다.

## 2. 세로 표를 가로 표로
> 화면: 실적 표 7행을 크게(부서 · 분기 · 매출 · 담당자 네 열 모두, 담당자 열 머리가 잠깐 밝게) → 오른쪽에 바꾸고 싶은 모양: 부서 2행 × 1분기 · 2분기 · 3분기 빈칸.

7. 오늘의 실적 표는 부서, 분기, 매출, 담당자 네 열에 7행입니다.
8. 영업은 1분기부터 4분기까지 다섯 건, 개발은 1분기와 3분기에 한 건씩입니다.
9. 부서마다 한 줄을 두고 분기를 옆으로 펼쳐서, 행에 있던 값을 열로 세우는 것이 PIVOT입니다.

## 3. PIVOT 문법
> 화면: SQL 카드 — SELECT * FROM (SELECT 부서, 분기, 매출 FROM 실적) / PIVOT (SUM(매출) FOR 분기 IN (1 AS Q1, 2 AS Q2, 3 AS Q3)) → 괄호 안 SELECT 줄 → SUM(매출) → FOR 분기 → IN 목록이 차례로 밝게, IN 목록 옆에 ‘1분기 → Q1’ 같은 작은 칩 세 개.

10. 먼저 FROM 절 괄호 안에서 부서, 분기, 매출 세 열만 골라 옵니다.
11. 이유는 조금 뒤에 보겠습니다.
12. PIVOT 괄호 안은 세 부분으로 되어 있습니다.
13. 첫째, SUM(매출)은 새로 생길 칸에 들어갈 값입니다.
14. PIVOT에는 이렇게 집계 함수가 반드시 들어갑니다.
15. 둘째, FOR 분기는 분기 열의 값을 펼쳐서 열로 만들겠다는 뜻입니다.
16. 셋째, IN 목록에 적은 값만 열이 되고, 값마다 붙인 별칭이 열 이름이 됩니다.
17. 1분기, 2분기, 3분기가 각각 Q1, Q2, Q3 열이 됩니다.

## 4. PIVOT 결과
> 화면: 왼쪽 실적 표 7행, 오른쪽 결과 표(부서 · Q1 · Q2 · Q3) → 영업 1분기 두 행이 밝아지며 90 + 60 = 150 → 2분기 120 · 3분기 110 → 4분기 130 행 흐려짐 + ‘IN 목록에 없음’ → 개발 70 · NULL · 80 → 표 머리 ‘2행’.

18. 결과는 부서마다 한 줄, 영업과 개발 두 줄입니다.
19. 영업의 1분기는 두 건이라, 90과 60을 더한 150이 들어갑니다.
20. 한 칸에 여러 행이 모이니, 집계 함수로 하나로 합치는 것입니다.
21. 2분기는 120, 3분기는 110입니다.
22. 영업 4분기 130은 IN 목록에 없어서 결과에서 빠집니다.
23. 개발은 1분기 70, 3분기 80이고, 2분기에는 데이터가 없습니다.
24. 이렇게 데이터가 없는 칸은 NULL로 채워집니다.
25. 7행이 PIVOT을 거쳐 2행이 되었습니다.

## 5. 남은 열로 묶인다
> 화면: SQL 카드에서 괄호(인라인 뷰)가 걷히고 FROM 실적 → 실적의 네 열 칩: 매출(SUM) · 분기(FOR)가 흐려지고 부서 · 담당자 칩만 밝게 ‘묶는 기준’ → 결과 표 3행(영업 민수 90 · 120 · 110 / 영업 지영 60 · NULL · NULL / 개발 현우 70 · NULL · 80), 영업 1분기 90 · 60 칸이 밝게 → 마지막에 인라인 뷰 SQL 다시 ✓ ‘인라인 뷰’.

26. 이제 처음 질문으로 돌아가 보겠습니다.
27. PIVOT에는 GROUP BY를 적지 않지만, 안에서 저절로 행을 묶습니다.
28. 묶는 기준은 집계 함수와 FOR에 나오지 않은 나머지 열 전부입니다.
29. 괄호 없이 실적 표에 바로 PIVOT을 하면, 담당자 열까지 그대로 들어옵니다.
30. 매출과 분기를 빼면 부서와 담당자가 남으니, 이 두 열로 묶입니다.
31. 그래서 영업이 민수와 지영, 두 줄로 갈라져 3행이 된 것입니다.
32. 영업 1분기 150도 90과 60으로 나뉘었습니다.
33. 필요한 열만 골라 넣는 FROM 절의 서브쿼리, 곧 인라인 뷰가 필요한 이유가 바로 이것입니다.

## 6. CASE로 쓰면
> 화면: SQL 카드 — SELECT 부서, SUM(CASE WHEN 분기 = 1 THEN 매출 END) AS Q1, (Q2 · Q3 같은 꼴) FROM 실적 GROUP BY 부서 → GROUP BY 부서 줄이 밝게 → 결과 2행(4장과 같음) ✓ → 아래 작은 줄 ‘SQL Server: IN ([1], [2], [3])’.

34. 같은 결과를 PIVOT 없이 CASE와 GROUP BY로도 만들 수 있습니다.
35. 분기가 1인 행에서만 매출을 돌려주는 CASE를 SUM으로 감싸면 Q1 열이 됩니다.
36. 분기마다 이렇게 적고 GROUP BY 부서로 묶으면, PIVOT과 똑같은 2행이 나옵니다.
37. 여기서는 묶는 기준을 직접 적었으니, 담당자 열이 있어도 결과가 갈라지지 않습니다.
38. SQL Server도 PIVOT을 쓰는데, IN 목록에는 별칭 없이 값을 대괄호로 감싸 적습니다.

## 7. UNPIVOT
> 화면: 4장 결과 2행이 ‘분기실적’ 표로 → SQL 카드 ‘SELECT * FROM 분기실적 UNPIVOT (매출 FOR 분기 IN (Q1, Q2, Q3))’ → 칸 여섯 개가 한 행씩 세로로 풀려 내려오고(부서 · 분기 · 매출) 개발 Q2 NULL 칸은 흐려져 빠짐 → 표 머리 ‘5행’ → SQL 카드에 INCLUDE NULLS가 끼어들며 개발 Q2 NULL 행이 생겨 ‘6행’ → 마지막에 ‘PIVOT을 되돌리지 못함’ — 150 칸 옆에 ‘90 + 60으로 안 나뉨’, 흐린 4분기 130에 ‘돌아오지 않음’.

39. 이번에는 반대로, 열을 행으로 바꾸는 UNPIVOT입니다.
40. 방금 만든 2행짜리 결과를 분기실적 표라고 해 보겠습니다.
41. UNPIVOT 괄호 안에는 먼저 값이 들어갈 새 열 이름, 매출을 적습니다.
42. FOR 뒤에는 원래 열 이름이 들어갈 새 열 분기를, IN 목록에는 풀어 낼 세 열을 적습니다.
43. 2행에 열이 세 개씩이니, 칸은 모두 여섯 개입니다.
44. 칸 하나가 한 행이 되고, 분기 칸에는 Q1 같은 원래 열 이름이 들어갑니다.
45. 그런데 결과는 5행, 개발의 Q2 칸이 NULL이라 빠졌습니다.
46. UNPIVOT은 따로 적지 않으면 NULL 칸을 행으로 만들지 않는데, 이것을 EXCLUDE NULLS라고 합니다.
47. NULL도 남기려면 UNPIVOT 바로 뒤에 INCLUDE NULLS를 적고, 그러면 6행이 나옵니다.
48. 하나 더, UNPIVOT은 PIVOT을 그대로 되돌리지 못합니다.
49. 90과 60을 합친 150은 다시 나뉘지 않고, 빠졌던 4분기 130도 돌아오지 않습니다.

## 8. 시험장 체크
> 화면: 체크 카드 세 장이 차례로.

50. 시험장에서 챙길 것 세 가지입니다.
51. 첫째, PIVOT은 집계 함수와 FOR에 없는 나머지 열로 묶이니, 필요한 열만 인라인 뷰로 골라 넣습니다.
52. 둘째, IN 목록에 적은 값만 열이 되고, 데이터가 없는 칸은 NULL입니다.
53. 셋째, UNPIVOT은 NULL 칸을 빼고, INCLUDE NULLS를 적어야 남깁니다.

## 9. 한 줄 정리
> 화면: 두 줄 정리 — ‘행 → 열 PIVOT · 남은 열로 묶임’ / ‘열 → 행 UNPIVOT · NULL은 빠짐’.

54. 오늘 내용을 한 줄로 정리하면 이렇습니다.
55. 행을 열로 세우는 PIVOT은 남은 열로 묶이고, 열을 행으로 푸는 UNPIVOT은 NULL을 뺍니다.
