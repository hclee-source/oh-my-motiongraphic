썸네일 문구: 윗줄 ‘누적합 기본 범위’ / 오해 ‘한 행씩?’ / 띠 ‘ROWS와 RANGE 차이’
예시 숫자(검수용): 직원 5행(급여, 만 원, 급여 순) 민수 영업 200 · 지영 영업 300 · 현우 개발 300 · 수진 개발 500 · 동훈 영업 700 (verify_examples.py로 sqlite 실행 확인)
  SUM(급여) OVER () → 모든 행 2000 (행 수 5 그대로) / OVER (PARTITION BY 부서) → 영업 200 + 300 + 700 = 1200, 개발 300 + 500 = 800
  SUM(급여) OVER (ORDER BY 급여) = 기본 범위 RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW → 200, 800, 800, 1300, 2000 (지영·현우 300은 같은 값이라 함께 포함: 200 + 300 + 300 = 800)
  ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW → 위치별 200, 500, 800, 1300, 2000 (300 두 행 중 누가 500인지는 정해지지 않음, 값은 동점 순서와 상관없이 같음)
  OVER (PARTITION BY 부서 ORDER BY 급여) → 영업 200, 500, 1200 / 개발 300, 800 (부서 안에 동점 없음 → ROWS도 같음)
  ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING → 200 + 300 = 500, 200 + 300 + 300 = 800, 300 + 300 + 500 = 1100, 300 + 500 + 700 = 1500, 500 + 700 = 1200
  LAG(급여) → NULL, 200, 300, 300, 500 / LAG(급여, 2, 0) → 0, 0, 200, 300, 300 / LEAD(급여) → 300, 300, 500, 700, NULL
  FIRST_VALUE(급여) OVER (ORDER BY 급여) → 200 × 5 / LAST_VALUE(급여) OVER (ORDER BY 급여) → 200, 300, 300, 500, 700 (기본 범위가 현재 행(같은 값 끝)에서 끝남) / + ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING → 700 × 5
  RATIO_TO_REPORT(급여) OVER () → 0.1, 0.15, 0.15, 0.25, 0.35 (수진 500 ÷ 2000 = 0.25) / RANK 1, 2, 2, 4, 5 → PERCENT_RANK (순위 − 1) ÷ (5 − 1) → 0, 0.25, 0.25, 0.75, 1 / CUME_DIST (나 이하 행 ÷ 5) → 0.2, 0.6, 0.6, 0.8, 1 (300 두 행: 3 ÷ 5) / NTILE(2) → 1, 1, 1, 2, 2 (5 = 3 + 2, 남는 한 행은 앞 묶음)
  오라클 기준: ORDER BY 없는 OVER는 파티션 전체, ORDER BY만 있으면 기본 범위 RANGE … CURRENT ROW(같은 정렬 값의 행 포함), LAG · LEAD는 범위 절을 쓰지 않음, LAST_VALUE(급여)가 자기 급여인 것은 정렬 기준도 급여이기 때문(같은 급여 끝 행 = 같은 값), RATIO_TO_REPORT는 오라클 전용 · OVER에 PARTITION BY만(ORDER BY 불가, sqlite에는 없어 급여 / SUM(급여) OVER ()로 확인), PERCENT_RANK · CUME_DIST · NTILE은 ORDER BY 필수

## 1. 같은 급여, 같은 누적합
> 화면: 어두운 SQL 카드 ‘SUM(급여) OVER (ORDER BY 급여)’ → 아래에 급여 칩 200 · 300 · 300 · 500 · 700 → 그 아래 누적 칩 200 · 800 · 800 · 1300 · 2000 → 두 번째 누적 칩 옆에 ‘500?’ → 800 두 칩을 한 테두리로 묶고 ‘왜?’.

1. SUM(급여) OVER (ORDER BY 급여)로 누적합을 구했습니다.
2. 급여는 200, 300, 300, 500, 700입니다.
3. 결과는 200, 800, 800, 1300, 2000입니다.
4. 두 번째 행은 200 더하기 300, 500이어야 할 것 같은데 800이 나왔습니다.
5. 급여가 같은 두 행은 왜 똑같이 800을 받았을까요?
6. 오늘은 이 질문으로 시작해 윈도우 함수의 범위를 정리해 보겠습니다.

## 2. 집계 함수에 OVER
> 화면: 흰 직원 표 5행(이름 · 부서 · 급여, 급여 순, 머리에 ‘5행’) + SQL 카드 ‘SUM(급여) OVER ()’ → 표 오른쪽에 새 칸이 붙고 2000이 다섯 행 모두에(머리 ‘5행’ 그대로) → SQL 카드가 ‘OVER (PARTITION BY 부서)’로 바뀌고 칸이 영업 세 행 1200 · 개발 두 행 800으로.

7. 직원 다섯 명을 급여 순으로 놓았고, 급여가 300으로 같은 사람은 지영과 현우입니다.
8. SUM(급여) 뒤에 OVER를 붙이고 괄호를 비워 두면, 전체 합계 2000이 모든 행에 붙습니다.
9. 순위 함수와 마찬가지로, 윈도우 함수는 행을 줄이지 않고 행마다 값을 하나씩 붙입니다.
10. 괄호 안에 PARTITION BY 부서를 적으면 부서별 합계가 붙어서, 영업 세 명은 1200, 개발 두 명은 800입니다.

## 3. ORDER BY를 넣으면 누적
> 화면: SQL 카드가 ‘SUM(급여) OVER (ORDER BY 급여)’로 → ‘누적’ 칸에 위에서부터 200 → 800 · 800(지영 · 현우 두 행이 동시에) → 1300 → 2000 → 2000 옆에 ‘= 전체 합계’.

11. 이번에는 괄호 안에 ORDER BY 급여를 적습니다.
12. 그러면 합계가 한꺼번에 붙지 않고, 급여 순으로 차곡차곡 쌓입니다.
13. 민수는 200, 지영과 현우는 200에 300을 두 번 더한 800을 똑같이 받습니다.
14. 이어서 수진은 1300, 동훈은 2000으로, 마지막 값은 전체 합계와 같습니다.

## 4. 생략된 범위, RANGE
> 화면: SQL 카드 ORDER BY 급여 아래에 흐린 줄이 나타남 ‘RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW’ → UNBOUNDED PRECEDING 아래 칩 ‘맨 처음 행부터’, CURRENT ROW 아래 칩 ‘현재 행까지’ → RANGE에 칩 ‘급여 값으로’ → 표에서 지영 · 현우(300) 두 행을 한 테두리로 묶고 누적 800 · 800 강조.

15. 이유는 적지 않고 생략한 범위에 있습니다.
16. OVER 안에 ORDER BY만 적으면, 범위는 RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW가 됩니다.
17. 맨 처음 행부터 현재 행까지 더하라는 뜻입니다.
18. 그런데 RANGE는 행을 하나씩 세지 않고, 정렬 기준인 급여 값으로 범위를 정합니다.
19. 그래서 현재 행과 급여가 같은 행은 모두 함께 범위에 들어갑니다.
20. 지영의 누적을 구할 때 같은 300인 현우까지 더해져서, 두 사람 모두 800이 된 겁니다.

## 5. 한 행씩 세는 ROWS
> 화면: 범위 줄의 RANGE가 ROWS로 바뀜 → 표에 ‘ROWS’ 칸 200 · 500 · 800 · 1300 · 2000이 붙고, 옆 ‘RANGE’ 칸(200 · 800 · 800 · 1300 · 2000)은 흐리게 → 300 두 행의 500 / 800 강조 → 지영 · 현우 옆에 ‘누가 먼저인지 정해지지 않음’.

21. 한 행씩 더하고 싶다면 RANGE 대신 ROWS를 적습니다.
22. ROWS는 실제 행 개수를 세므로, 결과는 200, 500, 800, 1300, 2000입니다.
23. 같은 300이어도 먼저 온 행은 500, 다음 행은 800으로 갈립니다.
24. 다만 지영과 현우 가운데 누가 먼저 오는지는 정해져 있지 않습니다.

## 6. 부서마다 다시 시작
> 화면: 표가 부서별 두 묶음으로 다시 놓임(영업 민수 200 · 지영 300 · 동훈 700 / 개발 현우 300 · 수진 500) → SQL 카드 ‘OVER (PARTITION BY 부서 ORDER BY 급여)’ → 누적 칸 영업 200 · 500 · 1200 / 개발 300 · 800 (묶음 경계에서 처음부터) → 칩 ‘ROWS로 적어도 같음’.

25. PARTITION BY 부서와 ORDER BY 급여를 함께 적으면, 부서가 바뀔 때마다 누적이 처음부터 다시 시작합니다.
26. 영업은 200, 500, 1200, 개발은 300, 800입니다.
27. 부서 안에는 같은 급여가 없으니, ROWS로 적어도 결과가 같습니다.

## 7. 앞뒤 몇 행만
> 화면: 급여 순 표로 돌아옴 → SQL 카드 ‘ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING’ → 세 행짜리 테두리가 위에서 한 칸씩 내려가며 칸에 500 · 800 · 1100 · 1500 · 1200 → 첫 행 · 마지막 행에서는 테두리가 두 행만.

28. ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING처럼 적으면, 바로 앞 행, 현재 행, 바로 뒤 행, 세 행만 더합니다.
29. 결과는 500, 800, 1100, 1500, 1200입니다.
30. 첫 행과 마지막 행은 이웃이 하나뿐이라, 200과 300, 500과 700처럼 두 행만 더합니다.

## 8. LAG와 LEAD
> 화면: 급여 순 표 오른쪽에 ‘LAG(급여)’ 칸 — 한 칸 위 급여에서 화살표 → NULL(회색) · 200 · 300 · 300 · 500 → ‘LAG(급여, 2, 0)’ 칸 0 · 0 · 200 · 300 · 300(두 칸 위 화살표, 칩 ‘2 = 두 행 앞’ · ‘0 = 없을 때’) → ‘LEAD(급여)’ 칸 300 · 300 · 500 · 700 · NULL(한 칸 아래 화살표).

31. LAG(급여)는 범위와 상관없이, 정렬 순서상 바로 앞 행의 급여를 그대로 가져옵니다.
32. 첫 행은 앞 행이 없어서 NULL이고, 그다음부터 200, 300, 300, 500입니다.
33. LAG(급여, 2, 0)처럼 적으면 두 행 앞의 급여를 가져오고, 가져올 행이 없을 때는 NULL 대신 0을 돌려줍니다.
34. 그래서 처음 두 행은 0이고, 세 번째 행부터 200, 300, 300입니다.
35. LEAD(급여)는 반대로 바로 뒤 행의 급여를 가져와서, 마지막 행이 NULL입니다.

## 9. LAST_VALUE의 함정
> 화면: SQL 카드 ‘FIRST_VALUE(급여) OVER (ORDER BY 급여)’ → 칸에 200 다섯 개 → SQL 카드 ‘LAST_VALUE(급여) OVER (ORDER BY 급여)’ → 칸 위에 ‘700?’ → 실제 칸 200 · 300 · 300 · 500 · 700(급여 칸과 똑같음) → 범위 줄 ‘ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING’ 추가 → 칸이 700 다섯 개로.

36. 기본 범위 때문에 생기는 함정이 하나 더 있습니다.
37. FIRST_VALUE(급여)는 범위의 첫 값을 가져오니, 모든 행이 가장 작은 급여 200을 받습니다.
38. 그렇다면 LAST_VALUE(급여)는 모든 행이 가장 큰 700을 받을까요?
39. 실제로는 각자 자기 급여가 그대로 나옵니다.
40. 급여로 정렬했으니, 현재 행에서 끝나는 기본 범위의 마지막 급여는 곧 자기 급여인 겁니다.
41. 맨 끝까지 보려면 ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING을 적어야 700이 나옵니다.

## 10. 비율 함수
> 화면: 급여 순 표(이름 · 급여) 오른쪽에 칸이 하나씩 — RATIO_TO_REPORT 0.1 · 0.15 · 0.15 · 0.25 · 0.35(수진 0.25에 ‘500 ÷ 2000’, SQL 칩 ‘OVER ()’ · ‘오라클 전용’) → SQL 칩 ‘OVER (ORDER BY 급여)’ → PERCENT_RANK 0 · 0.25 · 0.25 · 0.75 · 1(식 ‘(순위 − 1) ÷ (행 수 − 1)’, 맨 앞 0 · 맨 뒤 1 강조) → CUME_DIST 0.2 · 0.6 · 0.6 · 0.8 · 1(300 두 행에 ‘3 ÷ 5’) → NTILE(2) 1 · 1 · 1 · 2 · 2(3행 / 2행 묶음 테두리).

42. 비율 함수 RATIO_TO_REPORT는 전체 합계에 대한 비율로, 급여 500인 수진은 2000의 0.25입니다.
43. 이 함수는 오라클 전용이고, OVER 안에 ORDER BY 없이 PARTITION BY만 적을 수 있습니다.
44. 반면 PERCENT_RANK, CUME_DIST, NTILE은 OVER 안에 ORDER BY가 있어야 합니다.
45. PERCENT_RANK는 순위 빼기 1을 행 수 빼기 1로 나눈 값이라, 맨 앞 행이 0이고 맨 뒤 행이 1입니다.
46. CUME_DIST는 나보다 작거나 같은 행의 비율이라, 300인 두 사람은 5행 중 3행, 0.6입니다.
47. NTILE(2)는 행을 두 묶음으로 나누는데, 남는 한 행은 앞 묶음이 받아서 3행과 2행이 됩니다.

## 11. 시험장 체크
> 화면: 체크 카드 네 장이 차례로.

48. 시험장에서 챙길 것 네 가지입니다.
49. 첫째, OVER에 ORDER BY만 적으면 기본 범위는 RANGE이고, 같은 값의 행은 같은 누적값을 받습니다.
50. 둘째, ROWS는 행 개수로, RANGE는 정렬한 값으로 범위를 정합니다.
51. 셋째, LAG는 앞 행, LEAD는 뒤 행의 값을 가져오고, 없으면 NULL이나 세 번째 인수로 적은 값이 나옵니다.
52. 넷째, LAST_VALUE로 마지막 값을 보려면 범위를 UNBOUNDED FOLLOWING까지 넓혀야 합니다.

## 12. 한 줄 정리
> 화면: 두 줄 정리 — ‘ORDER BY만 → RANGE, 같은 값은 함께’ / ‘한 행씩 → ROWS’.

53. 오늘 내용을 한 줄로 정리하면 이렇습니다.
54. ORDER BY만 적으면 RANGE라서 같은 값은 함께 더해지고, 한 행씩 더하려면 ROWS를 적습니다.
