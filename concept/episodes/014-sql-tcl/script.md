썸네일 문구: 윗줄 ‘ROLLBACK 하면’ / 오해 ‘처음으로?’ / 띠 ‘마지막 COMMIT까지만’
예시 숫자(검수용): 과일 표(이름, 수량) 커밋된 3행 사과 10 · 배 20 · 귤 30
  ① INSERT 감 40 → 4행(사과 10, 배 20, 귤 30, 감 40), 미확정
  ② SAVEPOINT A → 4행 그대로, 저장 지점 A
  ③ UPDATE 사과 수량 = 15 → 4행(사과 15, 배 20, 귤 30, 감 40)
  ④ SAVEPOINT B → 저장 지점 A, B
  ⑤ DELETE 배 → 3행(사과 15, 귤 30, 감 40)
  ⑥ ROLLBACK TO B → ⑤만 취소 → 4행(사과 15, 배 20, 귤 30, 감 40), 저장 지점 A, B 그대로
  ⑦ ROLLBACK TO A → ③ 취소(⑤는 이미 취소됨) → 4행(사과 10, 배 20, 귤 30, 감 40), B 지워지고 A만 남음(이 다음 ROLLBACK TO B는 오류, 오라클 ORA-01086)
  ⑧ COMMIT → 4행 확정, 저장 지점 모두 사라짐
  ⑨ DELETE 귤 → 3행(사과 10, 배 20, 감 40)
  ⑩ ROLLBACK → ⑧ 시점으로 → 답 4행(사과 10, 배 20, 귤 30, 감 40). ROLLBACK은 ⑥ ⑦ ⑩ 세 번
  같은 이름: SAVEPOINT A → 포도 추가 → SAVEPOINT A 다시(앞의 A 지워짐) → 키위 추가 → ROLLBACK TO A → 키위만 취소, 포도 남음
  DDL: 위 4행 확정 상태에서 UPDATE 귤 수량 = 0 → CREATE TABLE 주문 → (자동 COMMIT) → ROLLBACK → 귤 0 그대로(30으로 안 돌아감)
  오라클 규칙: DML은 COMMIT 전까지 미확정(본인은 바뀐 값이 보이고, 다른 사용자는 바뀌기 전 값, 바뀐 행은 잠금) / ROLLBACK TO x는 x 뒤의 변경만 취소, x 뒤에 만든 저장 지점은 지움, x는 남고 트랜잭션은 계속 / 이름 없는 ROLLBACK은 마지막 COMMIT 뒤 변경 전부 취소, 저장 지점 모두 지움 / COMMIT도 저장 지점 모두 지움 / 같은 이름 SAVEPOINT는 앞의 것을 지움 / DDL(CREATE, ALTER, DROP, TRUNCATE, RENAME)은 실행 앞뒤로 자동 COMMIT
  SQL Server: 기본 자동 커밋 모드(문장마다 바로 확정) / BEGIN TRANSACTION으로 시작한 트랜잭션 안에서는 대부분의 DDL도 ROLLBACK 가능 / 저장 지점 SAVE TRANSACTION 이름(되돌리기는 ROLLBACK TRANSACTION 이름)
  확인: verify_examples.py(sqlite3로 ①~⑩, 오류 두 가지, 같은 이름, DDL, 쇼츠 순서 재현. sqlite는 DDL 자동 COMMIT이 없어 DDL 앞뒤에 COMMIT을 넣어 오라클을 흉내)

## 1. ROLLBACK을 세 번 하면
> 화면: 오른쪽 과일 표 3행(사과 10 · 배 20 · 귤 30, 머리에 ‘3행’ · ‘커밋됨’), 왼쪽 열 줄 SQL 카드(①~⑩, 흐리게) → ROLLBACK 세 줄(⑥ ⑦ ⑩)만 밝게 → ‘3행?’ 칩에 ✕ → ‘4행’ 칩.

1. 과일 세 행이 커밋되어 있는 표에서, 명령 열 줄을 차례로 실행합니다.
2. 그 열 줄 사이에 ROLLBACK이 세 번이나 들어 있습니다.
3. 마지막에 이 표에는 몇 행이 남을까요?
4. 세 번이나 되돌렸으니 처음의 세 행일 것 같지만, 정답은 네 행입니다.
5. ROLLBACK이 언제나 처음으로 돌아가는 명령은 아니기 때문입니다.
6. 오늘은 이 열 줄을 한 줄씩 따라가며 COMMIT, ROLLBACK, SAVEPOINT를 정리해 보겠습니다.

## 2. 트랜잭션과 세 명령
> 화면: 카드 ‘트랜잭션 = 전부 반영 또는 전부 취소’ → 칩 네 개 원자성 · 일관성 · 격리성 · 지속성(원자성만 진하게) → 명령 카드 두 장 COMMIT ‘확정’ / ROLLBACK ‘취소’ → 아래 작은 카드 ‘COMMIT 전: 다른 사용자는 바뀌기 전 값 · 바뀐 행은 잠금’ → 셋째 명령 카드 SAVEPOINT ‘저장점 = 깃발’.

7. 오라클에서 INSERT, UPDATE, DELETE로 바꾼 내용은 바로 확정되지 않고, 하나의 트랜잭션으로 묶입니다.
8. 트랜잭션은 전부 반영되거나 전부 취소되어야 하는 작업 단위입니다.
9. 이 성질이 원자성이고, 일관성, 격리성, 지속성과 함께 트랜잭션의 네 가지 특성입니다.
10. COMMIT은 지금까지의 변경을 확정하고, ROLLBACK은 마지막 COMMIT 이후의 변경을 취소합니다.
11. COMMIT 전에는 다른 사용자에게 바뀐 내용이 보이지 않고, 바뀐 행은 다른 사용자가 고칠 수 없게 잠깁니다.
12. SAVEPOINT는 저장점이라고 부르며, 트랜잭션 중간에 이름을 붙여 꽂아 두는 깃발입니다.
13. ROLLBACK TO 뒤에 그 이름을 적으면, 그 깃발까지만 되돌립니다.

## 3. INSERT와 SAVEPOINT A
> 화면: 왼쪽 SQL 카드에서 지금 줄만 밝게(① → ②), 오른쪽 과일 표 3행 → ① 감 40 행이 바이올렛 글자(미확정)로 추가, 머리 ‘4행’ → ② 표 아래 저장 지점 줄에 깃발 칩 ‘A’.

14. 처음 표에는 사과 10, 배 20, 귤 30의 세 행이 커밋되어 있습니다.
15. 첫째 줄 INSERT로 감 40을 넣으면 네 행이 됩니다.
16. 아직 COMMIT하지 않았으니 감은 확정되지 않은 행입니다.
17. 그래도 지금 작업하는 사용자가 조회하면 감까지 네 행이 보입니다.
18. 둘째 줄에서 SAVEPOINT A를 만들어, 감이 들어간 지금 상태에 깃발 A를 꽂습니다.

## 4. UPDATE, SAVEPOINT B, DELETE
> 화면: ③ 사과 수량 10 → 15(바이올렛) → ④ 깃발 칩 ‘B’가 A 옆에 → ⑤ 배 행이 흐려지며 머리 ‘3행’.

19. 셋째 줄 UPDATE로 사과 수량을 15로 바꿉니다.
20. 넷째 줄에서 SAVEPOINT B를 만들어, 사과가 15인 지금 상태에 깃발 B를 꽂습니다.
21. 다섯째 줄 DELETE로 배를 지우면 세 행이 남습니다.
22. 지금 표는 사과 15, 귤 30, 감 40입니다.

## 5. ROLLBACK TO B
> 화면: ⑥ 줄 밝게 → 깃발 B 뒤의 작업 ⑤만 되돌아가 배 20이 다시 진하게, 머리 ‘4행’ → 사과 15는 그대로, 깃발 A · B 칩도 그대로.

23. 여섯째 줄 ROLLBACK TO B는 깃발 B 뒤에 한 일만 되돌립니다.
24. B 뒤에 한 일은 배를 지운 것 하나라서, 배가 돌아와 네 행이 됩니다.
25. B보다 앞에서 바꾼 사과 15는 그대로입니다.
26. 트랜잭션은 끝나지 않았고, 깃발 A와 B도 그대로 남아 있습니다.

## 6. ROLLBACK TO A
> 화면: ⑦ 줄 밝게 → 깃발 A 뒤의 작업 ③이 되돌아가 사과 15 → 10 → 감 40은 남아 머리 ‘4행’ 그대로 → 깃발 B 칩이 흐려지며 ✕, A만 남음 → 작은 칩 ‘ROLLBACK TO B → 오류’.

27. 일곱째 줄 ROLLBACK TO A는 깃발 A 뒤에 한 일을 모두 되돌립니다.
28. A 뒤에 남아 있던 일은 셋째 줄 UPDATE 하나라서, 사과가 15에서 다시 10이 됩니다.
29. A보다 앞에서 넣은 감은 되돌려지지 않아, 여전히 네 행입니다.
30. 이때 A보다 뒤에 꽂은 깃발 B는 지워지고, 깃발 A만 남습니다.
31. 그래서 이 다음에 ROLLBACK TO B를 하면 오류가 납니다.

## 7. COMMIT 다음의 ROLLBACK
> 화면: ⑧ COMMIT → 표의 바이올렛 글자가 모두 검정(확정), 머리 ‘커밋됨’, 깃발 A 칩 사라짐 → ⑨ 귤 행 흐려지며 ‘3행’ → ⑩ ROLLBACK → 귤 복귀 ‘4행’ → 결과 칩 ‘답 4행’.

32. 여덟째 줄 COMMIT으로 지금의 네 행이 확정됩니다.
33. COMMIT을 하면 트랜잭션이 끝나고, 남아 있던 깃발 A도 사라집니다.
34. 아홉째 줄 DELETE로 귤을 지우면 세 행이 됩니다.
35. 마지막 줄의 ROLLBACK은 이름이 없으니, 마지막 COMMIT 시점으로 돌아갑니다.
36. 귤이 돌아와서 답은 사과 10, 배 20, 귤 30, 감 40의 네 행입니다.
37. 이미 COMMIT한 감은 ROLLBACK으로도 지울 수 없습니다.

## 8. 같은 이름의 SAVEPOINT
> 화면: 가로 시간 줄 — 깃발 ‘A’ → ‘포도 추가’ → 깃발 ‘A’ 다시(앞의 A는 흐려지며 ✕) → ‘키위 추가’ → ROLLBACK TO A → ‘키위 추가’만 지워지고 ‘포도 추가’는 남음.

38. 저장 지점 이름이 겹치면 어떻게 될까요?
39. 같은 이름으로 SAVEPOINT를 다시 만들면, 앞의 지점은 지워지고 새 지점이 그 이름을 갖습니다.
40. SAVEPOINT A 다음에 포도를 넣고, 다시 A를 만든 뒤 키위를 넣었다고 해 보겠습니다.
41. 이제 ROLLBACK TO A를 하면 나중에 만든 A로 돌아가서, 키위만 취소되고 포도는 남습니다.

## 9. DDL은 자동으로 COMMIT
> 화면: 넓은 카드 ‘오라클의 DDL’에 CREATE · ALTER · DROP · TRUNCATE · RENAME이 말할 때 하나씩 찍히고 ‘실행하면 자동 COMMIT’ → 세 줄 SQL 카드 UPDATE(귤 수량 = 0) → CREATE TABLE 주문 → ROLLBACK, 오른쪽 과일 표(귤 30 → 0 바이올렛) → CREATE TABLE 줄 옆 칩 ‘자동 COMMIT’, 귤 0이 검정(확정) → ROLLBACK 줄에 ✕, 귤 0 그대로 → 아래 작은 카드 ‘SQL Server: 기본 자동 커밋 · BEGIN TRANSACTION 안에서는 DDL도 취소 · SAVE TRANSACTION’.

42. 오라클에서 하나 더 조심할 것이 DDL입니다.
43. CREATE, ALTER, DROP, TRUNCATE, RENAME 같은 DDL을 실행하면 자동으로 COMMIT이 일어납니다.
44. 예를 들어 UPDATE로 귤 수량을 0으로 바꾸고, CREATE TABLE을 실행한 다음 ROLLBACK을 해 보겠습니다.
45. 귤 수량은 30으로 돌아오지 않고 0 그대로입니다.
46. CREATE TABLE이 실행되는 순간, 앞의 UPDATE까지 함께 COMMIT되었기 때문입니다.
47. TRUNCATE로 지운 행을 ROLLBACK으로 되살릴 수 없는 것도 같은 이유입니다.
48. SQL Server는 기본이 자동 커밋 모드라, 문장 하나하나가 실행되자마자 확정됩니다.
49. 다만 BEGIN TRANSACTION으로 시작한 트랜잭션 안에서는 대부분의 DDL도 되돌릴 수 있고, 저장 지점은 SAVE TRANSACTION으로 만듭니다.

## 10. 시험장 체크
> 화면: 체크 카드 세 장이 차례로.

50. 시험장에서 챙길 것 세 가지입니다.
51. 첫째, ROLLBACK TO는 그 저장 지점 뒤의 작업만 되돌리고, 그 뒤에 만든 저장 지점도 함께 지웁니다.
52. 둘째, 이름 없는 ROLLBACK은 마지막 COMMIT 시점으로 돌아가고, 저장 지점도 모두 사라집니다.
53. 셋째, 오라클의 DDL은 자동으로 COMMIT되므로, 그 앞의 변경까지 되돌릴 수 없습니다.

## 11. 한 줄 정리
> 화면: 세 줄 정리 — ROLLBACK TO → 깃발까지 / ROLLBACK → 마지막 COMMIT까지 / DDL → 그 자리에서 COMMIT.

54. 오늘 내용을 한 줄로 정리하면 이렇습니다.
55. ROLLBACK TO는 깃발까지, 그냥 ROLLBACK은 마지막 COMMIT까지, DDL은 그 자리에서 COMMIT입니다.
