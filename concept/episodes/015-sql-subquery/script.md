예시 숫자(검수용): 직원 7행(이름, 부서, 급여 만 원) 영업 민수 300 · 지영 500 · 현우 700 / 개발 수진 400 · 동훈 600 / 인사 예린 350 · 서연 400
  부서 표 4행: 영업 · 개발 · 인사 · 기획(직원 없음). 검증 스크립트 verify_examples.py(sqlite3, ANY · ALL은 MIN · MAX와 EXISTS 두 방식으로 흉내 내 같은지 확인)
  1장: SELECT 이름 FROM 직원 WHERE 급여 = (SELECT 급여 FROM 직원 WHERE 부서 = '개발') → 서브쿼리 2행(400, 600) → 오라클 ORA-01427 오류(단일 행 연산자에 다중 행)
  3장: 급여 IN (개발 급여) → 400 또는 600 → 수진 400 · 서연 400 · 동훈 600 = 3행. IN = (= ANY), NOT IN = (<> ALL)
  4장: > ANY = 최솟값 400보다 큼 → 지영 500 · 동훈 600 · 현우 700 = 3행 / > ALL = 최댓값 600보다 큼 → 현우 700 = 1행
  5장: < ANY = 최댓값 600보다 작음 → 민수 300 · 예린 350 · 수진 400 · 서연 400 · 지영 500 = 5행 / < ALL = 최솟값 400보다 작음 → 민수 · 예린 = 2행
    서브쿼리 0행(예: WHERE 부서 = '기획'): > ALL → 7행 전부(오라클 문서: ALL은 0행이면 TRUE) / > ANY → 0행(ANY는 0행이면 FALSE)
  6장: WHERE a.급여 > (SELECT AVG(b.급여) FROM 직원 b WHERE b.부서 = a.부서) → 부서 평균 영업 (300 + 500 + 700) / 3 = 500, 개발 (400 + 600) / 2 = 500, 인사 (350 + 400) / 2 = 375
    민수 300 < 500 빠짐 / 지영 500 = 500 빠짐(초과 아님) / 서연 400 > 375 남음 → 결과 현우 · 동훈 · 서연 = 3행(서연 400 < 지영 500)
    서브쿼리는 메인쿼리 열을 쓸 수 있고, 메인쿼리는 WHERE 절 서브쿼리 안의 열을 쓸 수 없음
  7장: SELECT 부서명 FROM 부서 a WHERE EXISTS (SELECT 1 FROM 직원 b WHERE b.부서 = a.부서명) → 영업 · 개발 · 인사 = 3행 / NOT EXISTS → 기획 = 1행
    (NULL 편 연결 한 줄) 직원 부서에 NULL이 섞이면 부서명 NOT IN (SELECT 부서 FROM 직원) → 0행, NOT EXISTS → 기획 그대로
  8장: SELECT 절 = 스칼라 서브쿼리(한 행 한 열, 2행 이상 오류 ORA-01427, 0행 NULL) / FROM 절 = 인라인 뷰(ORDER BY 가능) / WHERE 절 = 중첩 서브쿼리, HAVING 절에도 사용 가능 / 인라인 뷰 말고는 서브쿼리 안 ORDER BY 불가(ORA-00907)
    다중 열: WHERE (부서, 급여) IN (SELECT 부서, MAX(급여) FROM 직원 GROUP BY 부서) → 현우 · 동훈 · 서연 3행, 오라클 가능 · SQL Server 불가
  화면의 SQL 문자열 '개발' '기획'은 SQL 따옴표(작은따옴표 ')로 적는다(강조 따옴표 아님, 검수에서 허용)
  읽는 법 약속: > ANY → 큰 애니, > ALL → 큰 올, < ANY → 작은 애니, < ALL → 작은 올, = ANY → 이퀄 애니, <> ALL → 낫 이퀄 올(say_manual.json)

## 1. 두 행이 돌아오면
> 화면: SQL 카드 — WHERE 급여 = (SELECT 급여 FROM 직원 WHERE 부서 = '개발') → 실행하면 등호 옆에 ✕ ‘오류’ → 괄호 안에서 결과 칩 400 · 600 두 개가 나옴 → 아래에 IN · ANY · ALL · EXISTS 칩 네 개.

1. 개발 부서 직원과 급여가 같은 직원을 찾으려고 이런 SQL을 적었습니다.
2. 그런데 실행하면 오류가 납니다.
3. 괄호 안 SELECT가 개발 부서 두 명의 급여, 400과 600을 한꺼번에 돌려주기 때문입니다.
4. 등호는 값 하나와만 비교할 수 있습니다.
5. 오늘은 직원 일곱 명의 표로, 여러 행이 돌아올 때 쓰는 IN과 ANY와 ALL을, 그리고 행이 있는지만 보는 EXISTS를 따라가 보겠습니다.

## 2. 서브쿼리와 돌아오는 행 수
> 화면: SQL 카드에서 괄호 안만 밝게 ‘서브쿼리’, 바깥 ‘메인쿼리’ 이름표 → 직원 표 7행(이름 · 부서 · 급여, 부서마다 묶어서) → 두 칸 카드 ‘결과 1행 → 단일 행 연산자(=, >, <)’ / ‘결과 여러 행 → 다중 행 연산자(IN · ANY · ALL)’.

6. SQL 안에 괄호로 넣은 SELECT를 서브쿼리, 바깥 SQL을 메인쿼리라고 합니다.
7. 메인쿼리와 상관없는 서브쿼리는 먼저 한 번 실행되고, 메인쿼리가 그 결과를 받아 비교합니다.
8. 오늘의 직원 표는 영업, 개발, 인사, 세 부서의 일곱 명입니다.
9. 서브쿼리 결과가 한 행이면 단일 행 서브쿼리로, 등호나 부등호로 비교합니다.
10. 결과가 여러 행이면 다중 행 서브쿼리로, IN이나 ANY, ALL 같은 다중 행 연산자를 써야 합니다.

## 3. IN
> 화면: 1장 SQL 카드의 ‘=’가 ‘IN’으로 바뀜 → 결과 칩 400 · 600 → 직원 표에서 400 · 600인 행(수진 · 서연 · 동훈)만 밝게, 표 머리 ‘3행’ → 서연 행의 ‘인사’ 강조 → 작은 카드 ‘IN = (= ANY)’ · ‘NOT IN = (<> ALL)’.

11. 먼저 등호를 IN으로 바꾸면, 결과 가운데 하나라도 같을 때 참이 됩니다.
12. 급여가 400이거나 600인 수진, 서연, 동훈, 세 행입니다.
13. 서연은 개발 부서가 아니지만, 급여가 400이라 함께 나옵니다.
14. IN은 ‘= ANY’와 같은 뜻이고, 반대로 NOT IN은 모든 값과 다르다는 ‘<> ALL’과 같습니다.

## 4. > ANY와 > ALL
> 화면: 급여 일곱 개를 작은 순으로 놓은 숫자 줄(300 민수 · 350 예린 · 400 수진 · 400 서연 · 500 지영 · 600 동훈 · 700 현우) 위에 결과 칩 400 · 600 → ‘> ANY’: 기준선이 400(최솟값)에 서고 500 · 600 · 700이 밝게, ‘3행’ → ‘> ALL’: 기준선이 600(최댓값)으로 옮겨 가 700만 남아 ‘1행’ → 아래 한 줄 ‘> ANY = 최솟값과 비교 / > ALL = 최댓값과 비교’.

15. 이번에는 개발 부서보다 급여가 많은 직원을 찾아 보겠습니다.
16. ‘개발 부서보다’는 누구 한 명보다라는 뜻일 수도, 모두보다라는 뜻일 수도 있습니다.
17. 앞의 뜻이 ‘> ANY’, 뒤의 뜻이 ‘> ALL’입니다.
18. ‘> ANY’는 400과 600 가운데 하나보다만 크면 되니, 가장 작은 400보다 크면 됩니다.
19. 지영 500, 동훈 600, 현우 700, 세 행입니다.
20. ‘> ALL’은 둘 모두보다 커야 하니, 가장 큰 600보다 커야 합니다.
21. 현우 700, 한 행만 남습니다.
22. 결국 ‘> ANY’는 최솟값과, ‘> ALL’은 최댓값과 비교하는 셈입니다.

## 5. 부등호를 뒤집으면
> 화면: 같은 숫자 줄 — ‘< ANY’: 기준선이 600으로, 왼쪽 다섯 개 밝게 ‘5행’ → ‘< ALL’: 기준선이 400으로, 300 · 350 두 개 ‘2행’ → 작은 카드 ‘ANY = 통과하기 쉬운 쪽 끝값 / ALL = 통과하기 어려운 쪽 끝값’ → 칩이 사라져 빈 괄호(0행, 기획 부서) → ‘> ALL → 7행’ · ‘> ANY → 0행’.

23. 부등호를 뒤집으면 비교할 끝값, 곧 최솟값과 최댓값도 서로 바뀝니다.
24. ‘< ANY’는 가장 큰 600보다 작으면 되니, 다섯 행입니다.
25. ‘< ALL’은 가장 작은 400보다 작아야 하니, 민수와 예린, 두 행입니다.
26. ANY는 통과하기 쉬운 쪽 끝값과, ALL은 통과하기 어려운 쪽 끝값과 비교한다고 기억하면 됩니다.
27. 하나 더, 직원이 없는 기획 부서처럼 서브쿼리 결과가 0행이면 비교할 값이 하나도 없습니다.
28. 그러면 ‘> ALL’은 어길 값이 없어 모든 행이 참이고, ‘> ANY’는 넘을 값이 없어 모든 행이 거짓입니다.

## 6. 연관 서브쿼리
> 화면: SQL 카드 WHERE a.급여 > (SELECT AVG(b.급여) FROM 직원 b WHERE b.부서 = a.부서), ‘a.부서’에 바이올렛 밑줄 → 직원 표 오른쪽에 ‘부서 평균’ 칸 → 민수 행 짚음(500, 300 ✕) → 지영(500, 같아서 ✕) → 서연(375, 400 ✓) → 나머지 칸이 채워지고 현우 · 동훈 · 서연만 밝게 ‘3행’ → 아래 한 줄 ‘서브쿼리 → 메인쿼리 열 ✓ / 메인쿼리 → 서브쿼리 열 ✕’.

29. 지금까지의 서브쿼리는 메인쿼리와 상관없이 한 번만 계산해도 되는 것들이었습니다.
30. 이번에는 자기 부서의 평균보다 급여가 많은 직원을 찾습니다.
31. 서브쿼리가 바깥 행의 부서를 가져다 쓰니, 바깥 행마다 평균을 다시 계산하는 셈입니다.
32. 이런 서브쿼리를 연관 서브쿼리, 또는 상관 서브쿼리라고 합니다.
33. 민수는 영업 평균 500보다 작아서 빠지고, 지영은 500으로 평균과 같아서 빠집니다.
34. 서연은 인사 평균 375보다 커서 남습니다.
35. 일곱 행을 모두 보면 현우, 동훈, 서연, 세 행입니다.
36. 서연은 지영보다 급여가 적어도, 자기 부서 평균보다 많아서 남는 겁니다.
37. 이렇게 서브쿼리는 메인쿼리의 열을 쓸 수 있지만, 메인쿼리는 WHERE 절 서브쿼리 안의 열을 쓸 수 없습니다.

## 7. EXISTS
> 화면: 부서 표 4행(영업 · 개발 · 인사 · 기획, 기획 옆 ‘직원 0명’) + SQL 카드 WHERE EXISTS (SELECT 1 FROM 직원 b WHERE b.부서 = a.부서명) → ‘SELECT 1’에 ‘값은 안 봄’ → 부서 행마다 ✓ ✓ ✓ ✕, ‘3행’ → EXISTS가 NOT EXISTS로 바뀌어 기획만 ‘1행’ → 작은 카드 ‘서브쿼리 결과에 NULL → NOT IN 0행 / NOT EXISTS 그대로’.

38. 이번에는 부서 표가 하나 더 있는데, 네 부서 가운데 기획에는 아직 직원이 없습니다.
39. EXISTS는 값을 비교하지 않고, 서브쿼리 결과가 한 행이라도 있으면 참, 한 행도 없으면 거짓입니다.
40. 행이 있는지만 보니, 안쪽 SELECT 뒤에는 보통 1을 적습니다.
41. 부서 행마다 직원 표를 확인하는 연관 서브쿼리로, 결과는 영업, 개발, 인사, 세 행입니다.
42. 반대로 없는 것을 찾는 NOT EXISTS는 기획 한 행을 돌려줍니다.
43. 서브쿼리 결과에 NULL이 섞였다면 NOT IN은 0행이 되지만, NOT EXISTS에는 그런 함정이 없습니다.

## 8. 서브쿼리가 들어가는 자리
> 화면: SQL 뼈대 카드 세 줄 — SELECT 이름, ( … ) / FROM ( … ) / WHERE 급여 > ( … ) → 줄마다 이름표 ‘스칼라 서브쿼리’ · ‘인라인 뷰’ · ‘중첩 서브쿼리’ → 스칼라 옆 ‘한 행 · 한 열’, 인라인 뷰 옆 ‘ORDER BY ✓’, 나머지 자리 ‘ORDER BY ✕’ → 아래 한 줄 ‘(부서, 급여) IN ( … ) 오라클 ✓ · SQL Server ✕’.

44. 서브쿼리는 들어가는 자리에 따라 이름이 다릅니다.
45. SELECT 절에 넣으면 스칼라 서브쿼리로, 한 행, 한 열만 돌려줘야 합니다.
46. 두 행 이상이면 오류, 0행이면 NULL이 됩니다.
47. FROM 절에 넣으면 인라인 뷰, WHERE 절에 넣으면 중첩 서브쿼리이고, HAVING 절에도 서브쿼리를 쓸 수 있습니다.
48. ORDER BY는 인라인 뷰에만 적을 수 있고, 다른 자리의 서브쿼리에는 적을 수 없습니다.
49. 두 열을 한꺼번에 비교하는 다중 열 서브쿼리는 오라클에서는 되고, SQL Server에서는 안 됩니다.

## 9. 시험장 체크
> 화면: 체크 카드 세 장이 차례로 → 마지막에 작은 카드 ‘SELECT 절 = 스칼라 서브쿼리 · FROM 절 = 인라인 뷰 · WHERE 절 = 중첩 서브쿼리’.

50. 시험장에서 챙길 것 세 가지입니다.
51. 첫째, 단일 행 연산자에 여러 행이 돌아오면 오류이고, 이때는 IN이나 ANY, ALL을 씁니다.
52. 둘째, ‘> ANY’는 최솟값보다 크다는 뜻이고, ‘> ALL’은 최댓값보다 크다는 뜻입니다.
53. 셋째, EXISTS는 결과 행이 있는지만 보고, 없는 것을 찾을 때는 NOT EXISTS를 씁니다.
54. 덧붙여, SELECT 절은 스칼라 서브쿼리, FROM 절은 인라인 뷰, WHERE 절은 중첩 서브쿼리입니다.

## 10. 한 줄 정리
> 화면: 세 줄 정리 — 한 행 → 등호 / 여러 행 → IN · ANY · ALL / 있는지만 → EXISTS.

55. 오늘 내용을 한 줄로 정리하면 이렇습니다.
56. 한 행이면 등호, 여러 행이면 IN과 ANY와 ALL, 있는지만 볼 때는 EXISTS입니다.
