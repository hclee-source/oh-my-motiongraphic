예시 숫자(검수용): 사원 7행(사원번호 이름 관리자번호) — 1 김대표 NULL / 2 이부장 1 / 3 박부장 1 / 4 최과장 2 / 5 정대리 2 / 6 한사원 4 / 7 윤과장 3
  조직도: 김대표 → 이부장 · 박부장 / 이부장 → 최과장 · 정대리 / 최과장 → 한사원 / 박부장 → 윤과장 (네 단계)
  순방향 SELECT LEVEL, 이름 FROM 사원 START WITH 관리자번호 IS NULL CONNECT BY PRIOR 사원번호 = 관리자번호 ORDER SIBLINGS BY 사원번호
    → 7행: 1 김대표, 2 이부장, 3 최과장, 4 한사원, 3 정대리, 2 박부장, 3 윤과장 (깊이 우선, 형제는 사원번호 순)
  같은 START WITH + CONNECT BY PRIOR 관리자번호 = 사원번호 → 1행(김대표, 관리자번호 NULL이라 사원번호 = NULL인 행 없음)
  역방향 START WITH 사원번호 = 6 + CONNECT BY PRIOR 관리자번호 = 사원번호 → 4행: 1 한사원, 2 최과장, 3 이부장, 4 김대표
  순방향 + WHERE 사원번호 <> 2 → 6행: 1 김대표, 3 최과장, 4 한사원, 3 정대리, 2 박부장, 3 윤과장 (다 펼친 뒤 이부장 한 행만 빠짐, LEVEL 그대로)
  순방향 + CONNECT BY PRIOR 사원번호 = 관리자번호 AND 사원번호 <> 2 → 3행: 1 김대표, 2 박부장, 3 윤과장 (이부장 가지 네 명 통째로 빠짐)
  CONNECT_BY_ISLEAF(순방향 순서) 0, 0, 0, 1, 1, 0, 1 → 1은 한사원 · 정대리 · 윤과장 / CONNECT_BY_ROOT 이름 → 모두 김대표
  SYS_CONNECT_BY_PATH(이름, 빗금) 한사원 행 → /김대표/이부장/최과장/한사원
  셀프 조인 FROM 사원 부하 JOIN 사원 상사 ON 부하.관리자번호 = 상사.사원번호(별칭은 따옴표 없는 한글 — 오라클 비인용 식별자, 표·열 이름이 한글인 것과 같은 규칙) → 6행(이부장-김대표, 박부장-김대표, 최과장-이부장, 정대리-이부장, 한사원-최과장, 윤과장-박부장), 김대표 빠짐
    LEFT OUTER JOIN → 7행(김대표-NULL 추가)
  오라클 규칙(문서 기준): PRIOR가 붙은 쪽 = 이미 읽은 부모 행 / 교재 표현 ‘PRIOR 자식 = 부모’(자식 = 사원번호 칸, 부모 = 관리자번호 칸)면 순방향, ‘PRIOR 부모 = 자식’이면 역방향 /
    형제 순서는 ORDER SIBLINGS BY 없으면 보장 안 됨 / ORDER BY는 계층 순서를 무시하고 전체 정렬 / WHERE는 계층을 다 만든 뒤 행마다 따로 거름(자식은 안 지움) /
    CONNECT BY 조건은 잇는 단계에서 걸러 그 아래가 이어지지 않음 / 고리 데이터는 오류(ORA-01436), NOCYCLE이면 고리에서 멈춤

## 1. PRIOR는 어느 쪽에
> 화면: SQL 카드 두 장 — 둘 다 START WITH 관리자번호 IS NULL, 마지막 줄만 다름(CONNECT BY PRIOR 사원번호 = 관리자번호 / CONNECT BY PRIOR 관리자번호 = 사원번호, PRIOR 글자 밝게) → 아래에 칩 ‘7행’ · ‘1행’, 어느 카드 것인지는 ‘?’.

1. 사원 표에서 김대표부터 시작해, 조직도를 위에서 아래로 펼치려고 합니다.
2. 두 SQL은 CONNECT BY 줄에서 PRIOR의 자리만 다릅니다.
3. 그런데 한쪽은 조직도 전체 7행, 다른 쪽은 김대표 1행만 나옵니다.
4. 아래로 내려가는 쪽은 어느 SQL일까요?
5. 오늘은 사원 일곱 명의 표로, 계층형 질의의 방향과 순서를 따라가 보겠습니다.

## 2. 사원 표 안의 조직도
> 화면: 사원 표 7행(사원번호 · 이름 · 관리자번호, 김대표의 관리자번호 NULL은 회색) → 오른쪽에 관리자번호를 따라 선이 이어진 조직도 네 단(김대표 / 이부장 · 박부장 / 최과장 · 정대리 · 윤과장 / 한사원).

6. 사원 표의 관리자번호 칸에는 직속 상사의 사원번호가 들어 있습니다.
7. 김대표는 상사가 없어 관리자번호가 NULL이고, 이부장과 박부장은 김대표 밑입니다.
8. 최과장과 정대리는 이부장 밑, 윤과장은 박부장 밑, 한사원은 최과장 밑입니다.
9. 이렇게 한 표 안의 위아래 관계를 따라 읽는 것이 계층형 질의입니다.

## 3. START WITH와 PRIOR
> 화면: 왼쪽 SQL 카드 네 줄(SELECT LEVEL, 이름 / FROM 사원 / START WITH 관리자번호 IS NULL / CONNECT BY PRIOR 사원번호 = 관리자번호), 오른쪽 조직도 → START WITH 줄 밝게, 김대표에 ‘루트’ → CONNECT BY 줄 밝게 → PRIOR 사원번호 아래 칩 ‘방금 읽은 행’, 관리자번호 아래 칩 ‘다음 행’ → 조직도에 아래 방향 화살표 → 1장의 ‘7행’ 칩이 이 카드에 붙는다.

10. START WITH는 출발 행을 정하는데, 관리자번호가 NULL인 김대표가 출발점, 곧 루트입니다.
11. CONNECT BY는 다음에 이어 읽을 행을 찾는 조건입니다.
12. 여기서 PRIOR가 붙은 열은 ‘방금 읽은 행’의 값입니다.
13. 그래서 PRIOR 사원번호 = 관리자번호는, 방금 읽은 사람의 사원번호를 관리자번호로 가진 행, 곧 부하를 찾습니다.
14. 부하를 찾아 내려가니, 7행이 나오는 쪽이 바로 이 SQL입니다.

## 4. 결과가 나오는 순서와 LEVEL
> 화면: SQL 카드에 다섯째 줄 ORDER SIBLINGS BY 사원번호가 붙음 → 결과 표(LEVEL · 이름)가 한 행씩 채워짐: 1 김대표 → 2 이부장 → 3 최과장 → 4 한사원 → 3 정대리 → 2 박부장 → 3 윤과장, 조직도에서 지금 읽는 사람이 밝아지고 순서 번호 ①~⑦이 붙음 → 표 머리 ‘7행’ → 마지막 줄을 ORDER BY로 바꾸면 ✕ ‘계층 순서가 깨짐’.

15. 같은 상사를 둔 형제끼리는 ORDER SIBLINGS BY 사원번호로, 번호 순으로 읽게 했습니다.
16. 첫 행은 출발점 김대표, LEVEL 1이고, 다음은 번호가 작은 이부장, LEVEL 2입니다.
17. 그다음은 박부장이 아니라, 이부장의 부하 최과장이 LEVEL 3입니다.
18. 최과장 밑의 한사원이 LEVEL 4, 더 내려갈 곳이 없으니 이부장의 다른 부하 정대리가 LEVEL 3입니다.
19. 이부장 밑을 다 읽고서야 박부장이 LEVEL 2, 윤과장이 LEVEL 3으로 나와, 모두 7행입니다.
20. 한 사람의 아래를 끝까지 먼저 읽고 옆 형제로 넘어가며, LEVEL은 한 단계 이어질 때마다 1씩 커집니다.
21. 여기서 ORDER SIBLINGS BY 대신 ORDER BY를 적으면, 결과 전체가 다시 정렬돼 이 순서가 깨집니다.

## 5. 방향을 바꾸면
> 화면: CONNECT BY 줄이 PRIOR 관리자번호 = 사원번호로 바뀜 → 김대표 위로 짧은 화살표, 끝에 ‘상사 없음’ → 결과 1행(1장의 ‘1행’ 칩) → START WITH 줄이 사원번호 = 6으로 바뀜 → 한사원 → 최과장 → 이부장 → 김대표 위로 화살표, 결과 표 LEVEL 1 한사원 · 2 최과장 · 3 이부장 · 4 김대표(4행) → 칩 ‘순방향 ↓’ · ‘역방향 ↑’.

22. 이번에는 PRIOR를 관리자번호 쪽으로 옮겨 보겠습니다.
23. 그러면 방금 읽은 사람의 관리자번호를 사원번호로 가진 행, 곧 상사를 찾아 올라갑니다.
24. 그런데 김대표는 관리자번호가 NULL이라 상사가 없으니, 1행만 나오고 끝납니다.
25. 출발점을 한사원으로 바꾸면 한사원부터 최과장, 이부장, 김대표까지, LEVEL 1부터 4까지 4행이 나옵니다.
26. 위에서 아래로는 순방향, 아래에서 위로는 역방향이고, 역방향에서도 출발 행의 LEVEL이 1이라 한사원이 1입니다.

## 6. 조건을 어디에 적느냐
> 화면: 순방향 결과 7행 두 벌 나란히 — 왼쪽 머리 ‘WHERE 사원번호 <> 2’: 이부장 행만 흐려져 6행(최과장 3 · 한사원 4 · 정대리 3 그대로) / 오른쪽 머리 ‘CONNECT BY … AND 사원번호 <> 2’: 이부장 · 최과장 · 한사원 · 정대리 네 행이 흐려져 3행, 작은 조직도에서 이부장 가지에 자르는 선.

27. 자주 나오는 함정은 조건을 어디에 적느냐입니다.
28. 먼저 이부장 한 사람을 빼는 조건을 WHERE에 적어 보겠습니다.
29. WHERE는 계층을 다 펼친 다음, 행을 하나씩 따로 거릅니다.
30. 그래서 이부장 한 행만 빠지고, 그 아래 세 명은 LEVEL도 그대로 남아 6행입니다.
31. 같은 조건을 CONNECT BY에 AND로 붙이면, 김대표에서 이부장으로 아예 이어 가지 않습니다.
32. 이부장과 그 아래 세 명이 통째로 빠져, 김대표, 박부장, 윤과장, 3행만 남습니다.
33. WHERE는 그 행만 지우고, CONNECT BY는 가지째 잘라 냅니다.

## 7. 계층형 질의 전용 함수
> 화면: 순방향 결과 표(7행)에 칸이 붙음 — ISLEAF 0 · 0 · 0 · 1 · 1 · 0 · 1(한사원 · 정대리 · 윤과장 행 밝게) → ROOT 칸 모두 김대표 → 한사원 행 옆 경로 카드 ‘/김대표/이부장/최과장/한사원’.

34. 전용 함수 가운데 CONNECT_BY_ISLEAF는 아래로 이어지는 행이 없으면 1, 있으면 0이라, 한사원, 정대리, 윤과장만 1입니다.
35. CONNECT_BY_ROOT는 루트의 값, SYS_CONNECT_BY_PATH는 루트부터 그 행까지의 경로를 보여 줍니다.

## 8. 셀프 조인
> 화면: SQL 카드(FROM 사원 부하 JOIN 사원 상사 ON 부하.관리자번호 = 상사.사원번호) + 같은 사원 표 두 장, 머리에 별칭 ‘부하’ · ‘상사’ → 관리자번호에서 사원번호로 선 연결 → 결과 표(부하 · 상사) 6행: 이부장 김대표 / 박부장 김대표 / 최과장 이부장 / 정대리 이부장 / 한사원 최과장 / 윤과장 박부장, 김대표는 짝 없음 → JOIN이 LEFT OUTER JOIN으로 바뀜 → 맨 위에 김대표 · NULL(회색) 추가 7행.

36. 상사 이름을 옆 칸에 붙일 때는 셀프 조인이 편합니다.
37. 같은 사원 표를 두 번 불러와, 하나에는 부하, 다른 하나에는 상사라는 별칭을 붙입니다.
38. 조인 조건은 부하의 관리자번호와 상사의 사원번호가 같다는 것입니다.
39. 그러면 사원과 상사가 한 행에 나란히 붙는데, 결과는 7행이 아니라 6행입니다.
40. 관리자번호가 NULL인 김대표는 짝이 되는 상사가 없어, INNER JOIN에서 빠지기 때문입니다.
41. LEFT OUTER JOIN으로 바꾸면, 상사 칸이 NULL인 김대표까지 살아나 7행이 됩니다.

## 9. 시험장 체크
> 화면: 체크 카드 세 장이 차례로(첫 카드 아래 작은 줄 ‘교재: PRIOR 자식 = 부모 → 순방향, 자식 = 사원번호 · 부모 = 관리자번호’) → 마지막에 작은 카드 두 칩 ‘고리 데이터 = NOCYCLE(없으면 오류)’ · ‘SQL Server = 재귀 WITH’.

42. 시험장에서 챙길 것 세 가지입니다.
43. 첫째, PRIOR를 사원번호에 붙이면 아래로 내려가는 순방향, 관리자번호에 붙이면 위로 올라가는 역방향입니다.
44. 교재에서는 PRIOR 자식 = 부모를 순방향이라고 외우는데, 여기서 자식 칸이 사원번호, 부모 칸이 관리자번호입니다.
45. 둘째, 출발 행의 LEVEL은 1이고, 결과는 한 가지를 끝까지 읽고 옆 형제로 넘어갑니다.
46. 셋째, WHERE는 펼친 뒤 그 행만 거르고, CONNECT BY 조건은 가지째 잘라 냅니다.
47. 덧붙여, 고리처럼 되돌아오는 데이터는 NOCYCLE이 없으면 오류가 나고, SQL Server는 재귀 WITH 절로 같은 일을 합니다.

## 10. 한 줄 정리
> 화면: 네 줄 정리 — START WITH = 출발 행 / PRIOR = 방금 읽은 행 / WHERE = 그 행만 / CONNECT BY 조건 = 가지째.

48. 오늘 내용을 한 줄로 정리하면 이렇습니다.
49. 출발은 START WITH, PRIOR는 방금 읽은 행, 한 행만 빼면 WHERE, 가지째 자르면 CONNECT BY입니다.
