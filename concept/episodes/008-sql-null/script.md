예시 숫자(검수용): 학생 5명 점수 민수 90, 지영 80, 현우 70, 수진 80, 동훈 NULL

  점수 = NULL → 0행 / 점수 IS NULL → 1행(동훈) / 점수 <> 80 → 2행(90, 70) / 점수 IN (80, NULL) → 2행 / 점수 NOT IN (80, NULL) → 0행

## 1. 평균은 몇 점일까
> 화면: 학생 표 5행(동훈 칸만 NULL) → ‘AVG(점수) = ?’ → 64와 80 두 카드 → 80에 ✓.

1. 학생 다섯 명 가운데 한 명이 시험을 보지 않아 점수 칸이 비어 있습니다.
2. 나머지 네 명의 점수는 90, 80, 70, 80입니다.
3. 이 표에서 AVG로 평균을 구하면 몇 점이 나올까요?
4. 다섯 명으로 나눈 64점일까요, 네 명으로 나눈 80점일까요?
5. 정답은 80점입니다.
6. 오늘은 이 빈칸, NULL이 SQL 곳곳에서 만드는 함정을 정리해 보겠습니다.

## 2. NULL은 모르는 값
> 화면: NULL 카드 ‘0 아님 · 공백 아님 · 모르는 값’ → 동훈 점수 + 10 = NULL.

7. NULL은 0도 아니고 띄어쓰기 같은 공백 문자도 아닌, 아직 모르는 값입니다.
8. 그래서 계산에 NULL이 끼면 결과도 대부분 NULL이 됩니다.
9. 동훈의 점수에 10을 더해도 결과는 NULL입니다.
10. 이 성질이 집계 함수, 비교, NOT IN에서 각각 다른 모습으로 나타납니다.

## 3. 집계 함수는 NULL을 건너뛴다
> 화면: 학생 표 옆 결과 카드 — COUNT(*) 5 / COUNT(점수) 4 / SUM 320 / AVG 80, 계산할 때 동훈 행이 흐려진다.

11. 먼저 집계 함수는 행 안의 덧셈과 달리, NULL을 만나도 결과가 NULL이 되지 않습니다.
12. COUNT(*)는 행의 개수를 세므로 5입니다.
13. COUNT(점수)는 점수가 NULL이 아닌 행만 세서 4입니다.
14. SUM(점수)는 NULL을 빼고 더해 320입니다.
15. AVG(점수)도 NULL을 빼고 계산하니 320을 4로 나눈 80입니다.
16. COUNT(*)만 빼면, 집계 함수는 NULL을 아예 없는 것처럼 건너뜁니다.

## 4. 0점으로 치면
> 화면: 동훈 칸 NULL → NVL로 0 → 320 ÷ 5 = 64, 옆에 SUM(점수) ÷ COUNT(*) = 64.

17. 시험을 안 본 학생을 0점으로 치고 싶다면 NULL을 0으로 바꿔야 합니다.
18. NVL(점수, 0)은 점수가 NULL이면 0을 돌려줍니다.
19. 그러면 합은 그대로 320, 나누는 수는 5가 되어 평균은 64입니다.
20. SUM(점수)를 COUNT(*)로 나눠도 같은 64가 나옵니다.
21. AVG(점수)는 언제나 80이고, 0점으로 치라는 조건이 있을 때만 NVL로 64를 구합니다.

## 5. 비교하면 알 수 없음
> 화면: WHERE 점수 = NULL → 0행 / IS NULL → 동훈 1행 / 점수 <> 80 → 90·70 두 행, 동훈 행에 ‘?’.

22. 이번에는 WHERE 절입니다.
23. 점수가 NULL인 학생을 찾으려고 ‘점수 = NULL’이라고 쓰면, 결과는 0행입니다.
24. NULL과 비교하면 참도 거짓도 아닌 ‘알 수 없음’이 되고, WHERE는 참인 행만 남기기 때문입니다.
25. NULL을 찾을 때는 IS NULL, 아닌 것을 찾을 때는 IS NOT NULL을 씁니다.
26. 비슷한 함정이 하나 더 있습니다.
27. 점수가 80이 아닌 학생을 찾으면 셋이 아니라 둘, 90점과 70점만 나옵니다.
28. 동훈은 점수가 80이 아닌지도 알 수 없어서 빠지는 겁니다.

## 6. NOT IN의 함정
> 화면: IN (80, NULL) → 2행 / NOT IN (80, NULL) → ‘80과 다르다 AND NULL과 다르다’ → 뒤쪽이 늘 ‘알 수 없음’ → 0행.

29. NULL의 함정 가운데 가장 자주 나오는 것이 NOT IN입니다.
30. ‘점수 IN (80, NULL)’은 80점인 두 명만 찾고, 점수가 NULL인 동훈은 찾지 못합니다.
31. 그런데 ‘점수 NOT IN (80, NULL)’은 한 명도 돌려주지 않습니다.
32. NOT IN은 ‘80과 다르고, 그리고 NULL과도 다르다’라는 뜻입니다.
33. 그런데 NULL과의 비교는 늘 ‘알 수 없음’이 되므로, 조건 전체가 참이 될 수 없습니다.
34. 값 목록이든 서브쿼리 결과든, NULL이 하나라도 섞여 있으면 NOT IN은 빈 결과를 냅니다.

## 7. NULL을 다루는 함수
> 화면: 함수 카드 네 장 — NVL · NVL2 · COALESCE · NULLIF, 각각 한 줄 뜻.

35. NULL을 다루는 함수는 네 개만 기억하면 됩니다.
36. NVL(A, B)는 A가 NULL이면 B를, 아니면 A를 그대로 돌려줍니다.
37. NVL2(A, B, C)는 A가 NULL이 아니면 B, NULL이면 C를 돌려줍니다.
38. COALESCE는 괄호 안에서 처음으로 NULL이 아닌 값을 돌려줍니다.
39. NULLIF(A, B)는 반대로, A와 B가 같으면 NULL을, 다르면 A를 돌려줍니다.

## 8. 정렬과 NULL
> 화면: 점수 오름차순 목록 — 오라클은 NULL이 맨 뒤, 내림차순이면 맨 앞 / SQL Server는 오름차순 맨 앞.

40. 정렬할 때도 NULL은 따로 자리를 잡습니다.
41. 오라클은 NULL을 가장 큰 값으로 보아, 오름차순이면 맨 뒤, 내림차순이면 맨 앞에 둡니다.
42. SQL Server는 반대로 가장 작은 값으로 보아, 오름차순에서 맨 앞에 둡니다.

## 9. 시험장 체크
> 화면: 체크 카드 세 장.

43. 시험장에서 챙길 것 세 가지입니다.
44. 첫째, COUNT(*)만 NULL이 있는 행까지 세고, 나머지 집계 함수는 NULL을 건너뜁니다.
45. 둘째, NULL은 IS NULL로 찾고, NOT IN 목록에 NULL이 있으면 결과는 0행입니다.
46. 셋째, 오라클은 NULL을 가장 큰 값으로 보아 오름차순에서 맨 뒤에 둡니다.

## 10. 한 줄 정리
> 화면: 세 줄 정리.

47. 오늘 내용을 한 줄로 정리하면 이렇습니다.
48. NULL은 모르는 값, 집계에서는 빠지고, 비교하면 알 수 없음이 됩니다.
