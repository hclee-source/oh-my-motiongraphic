  고객(고객번호 / 이메일, 이름 — 이메일은 가입 때 중복 불가로 가정) · 주문(주문번호 / 주문일자, 고객번호) · 상품(상품코드 / 상품명, 가격) · 주문상품(주문번호 + 상품코드 / 수량)
  관계(IE 표기): 고객–주문 1:M 비식별자 관계(점선), 고객 쪽 끝 세로줄 두 개(하나·필수), 주문 쪽 끝 ○ + 까마귀발(선택·여러)
    주문–주문상품 1:M 식별자 관계(실선), 주문 쪽 세로줄 두 개, 주문상품 쪽 세로줄 + 까마귀발(주문에는 상품이 하나 이상)
    상품–주문상품 1:M 식별자 관계(실선), 상품 쪽 세로줄 두 개, 주문상품 쪽 ○ + 까마귀발(한 번도 안 팔린 상품 가능)
    주문–상품 M:N → 가운데 주문상품이 1:M 두 개로 풀어 줌
  관계 읽기(기준 엔터티는 ‘각’, 상대편 끝 기호로 개수와 항상/때때로): 고객→주문 ‘각 고객은 여러 주문을 때때로 한다’ / 주문→고객 ‘각 주문은 한 고객에게 항상 속한다’
  주식별자 특징 예: 유일성 = 주문번호 하나에 주문 한 건 / 최소성 = 주문번호 + 주문일자 ✕(주문번호만으로 유일) / 불변성 = 정한 주문번호는 안 바뀜 / 존재성 = NULL 불가
  주문상품을 두 속성으로 구분하는 이유: 주문번호만(한 주문에 상품 여럿), 상품코드만(한 상품이 여러 주문에)으로는 유일하지 않음
  식별자 분류 예: 대표성 주식별자 고객번호 / 보조식별자 이메일 · 스스로 생성 내부식별자 주문번호 / 외부식별자 주문의 고객번호 · 속성 수 단일식별자 주문번호 / 복합식별자 주문번호 + 상품코드 · 대체 여부 본질식별자 주문번호 + 상품코드 / 인조식별자 주문상품번호
  식별자 관계만 이으면: 주문상품 아래 배송(가정: 분할 배송 기록, 모델의 네 엔터티 밖) 주식별자 = 주문번호 + 상품코드 + 배송순번 → 3칸
  선택 관계 → 비식별자: 일반론으로만 말함(이 모델의 고객–주문은 고객 쪽 필수). 비어 있을 수 있는 값은 존재성 때문에 주식별자가 못 됨
  IE 세로줄 두 개 = 최소 1 · 최대 1 = 반드시 딱 하나
  존재에 의한 관계 = 엔터티의 상태(소속)로 연결, 행위에 의한 관계 = 엔터티 간 행위(주문)로 발생
  비식별자 관계: 고객번호는 주문의 일반 속성이라 주문상품까지 내려가지 않음 → 고객별 주문상품은 주문상품과 주문을 조인해야 함(verify_examples.py에서 확인)
  인조식별자 표 주문상품 4행(주문상품번호, 주문번호, 상품코드, 수량): 1, 1001, P01, 2 / 2, 1001, P02, 1 / 3, 1002, P01, 3 / 4, 1001, P01, 2
    주식별자 주문상품번호 → 4행 모두 들어감(1행과 4행은 주문번호·상품코드 같음) / 주식별자 주문번호 + 상품코드 → 4행 거부, 3행
    인조식별자에 UNIQUE(주문번호, 상품코드)를 더하면 인덱스 2개(주식별자 인덱스 + UNIQUE 인덱스, 오라클은 UNIQUE 제약에 유일 인덱스를 자동으로 만듦)
  근거(SQL 전문가 가이드 1과목, 출제기준 1.1.4 관계): 관계 표기 = 관계명·관계차수·관계선택사양, 차수 1:1·1:M·M:N, 선택사양 필수참여·선택참여, IE 표기에서 까마귀발 = 여러, 선택참여 = ○, 관계 읽기 순서(기준 엔터티 ‘각’ → 대상 개수 → 항상/때때로·관계명), 관계 분류 = 존재에 의한 관계(부서–사원)·행위에 의한 관계(고객–주문)
  근거(1.1.5 식별자): 식별자 = 엔터티 내 인스턴스를 구분하는 구분자, 주식별자 특징 유일성·최소성·불변성·존재성, 분류 대표성(주식별자·보조식별자, 보조는 대표성이 없어 참조 관계 연결에 안 씀)·스스로 생성(내부·외부, 외부식별자는 DB 생성 때 FK 역할)·속성 수(단일·복합)·대체 여부(본질·인조)
    식별자관계 = 부모 주식별자가 자식 주식별자 구성에 포함, 강한 연결, 실선 / 비식별자관계 = 자식 일반 속성, 약한 연결, 점선, 부모 없는 자식이 생길 수 있을 때(선택관계)·자식 주식별자를 독립적으로 구성할 때·상속받은 주식별자를 아래로 차단할 때
    식별자관계만 → 주식별자 속성이 계속 늘어 개발 복잡·오류 가능성 / 비식별자관계만 → 상위 엔터티 정보 조회 때 불필요한 조인 증가
  근거(1.2.5 본질식별자 vs 인조식별자): 본질식별자 = 업무에 의해 만들어지는 식별자, 인조식별자 = 원조식별자가 복잡해 인위적으로 만든 식별자(일련번호), 인조식별자 단점 = 중복 데이터 발생 가능성(데이터 품질 저하)·불필요한 인덱스 생성(저장 공간 낭비, DML 성능 저하) → 꼭 필요한 경우에만

## 1. 일련번호 하나면 될까
> 화면: 주문상품 상자 — 가로선 위 ‘주문번호 · 상품코드’, 아래 ‘수량’ → 오른쪽에 가로선 위가 ‘주문상품번호’ 하나뿐인 상자가 나란히 → 두 상자 사이에 ‘?’.

1. 주문 한 건에 담긴 상품을 기록하는 주문상품은, 주문번호와 상품코드를 합쳐 한 건을 구분합니다.
2. 두 칸짜리가 번거로우니, ‘주문상품번호’라는 일련번호 하나로 바꾸면 깔끔해 보입니다.
3. 그런데 이렇게 바꾸는 순간, 막지 못하는 데이터가 생깁니다.
4. 오늘은 주문 모델 하나로 식별자와 관계를 정리하며 답을 찾아보겠습니다.

## 2. 상자 읽는 법
> 화면: 네 상자가 차례로 — 고객(고객번호 / 이메일 · 이름), 주문(주문번호 / 주문일자 · 고객번호), 상품(상품코드 / 상품명 · 가격), 주문상품(주문번호 · 상품코드 / 수량). 상자마다 가로선 위 칸은 바이올렛 글자.

5. 오늘의 모델은 고객, 주문, 상품, 주문상품, 네 엔터티입니다.
6. 상자 하나가 엔터티이고, 가로선 위에는 주식별자, 아래에는 나머지 속성을 적습니다.
7. 식별자는 엔터티 안에서 인스턴스 하나하나를 구분하는 속성입니다.

## 3. 관계의 표기
> 화면: 고객과 주문 사이에 선이 그어진다 → 칩 세 개 ‘관계명 · 관계차수 · 관계선택사양’ → 차수 ‘1:1 · 1:M · M:N’, 선택사양 ‘필수 · 선택’ → IE 기호 범례 세 줄(까마귀발 = 여러, ○ = 선택, 세로줄 = 하나 · 필수) → 넷째 줄 ‘세로줄 두 개 = 반드시 딱 하나’.

8. 엔터티를 잇는 선이 관계이고, 관계명, 관계차수, 관계선택사양, 세 가지로 표기합니다.
9. 관계차수는 관계에 참여하는 수로, 일대일, 일대다, 다대다가 있습니다.
10. 관계선택사양은 반드시 참여해야 하면 필수, 참여하지 않아도 되면 선택입니다.
11. IE 표기법에서는 까마귀발이 ‘여러’, 동그라미가 ‘선택’, 세로줄이 ‘하나’ 또는 ‘필수’입니다.
12. 그래서 세로줄이 두 개 겹치면 ‘반드시 딱 하나’라는 뜻입니다.

## 4. 관계 읽기
> 화면: 고객 — 주문 선 — 주문 쪽 끝 ○ + 까마귀발, 고객 쪽 끝 세로줄 두 개 → 읽기 문장 두 줄이 차례로 ‘각 고객은 여러 주문을 때때로 한다’ / ‘각 주문은 한 고객에게 항상 속한다’.

13. 관계를 읽을 때는 기준 엔터티에서 출발해, 상대편 끝에 붙은 기호를 봅니다.
14. 고객에서 읽으면 주문 쪽 끝이 동그라미와 까마귀발이니, ‘각 고객은 여러 주문을 때때로 한다’입니다.
15. 가입만 하고 아직 주문하지 않은 고객도 있으니 선택입니다.
16. 주문에서 읽으면 고객 쪽 끝이 세로줄 두 개이니, ‘각 주문은 한 고객에게 항상 속한다’입니다.

## 5. 주식별자의 네 가지 특징
> 화면: 주문 상자의 ‘주문번호’에 바이올렛 테두리 → 카드 네 장이 차례로 — 유일성 ‘주문번호 하나 = 주문 한 건’ / 최소성 ‘주문번호 + 주문일자 ✕’ / 불변성 ‘정한 번호는 그대로’ / 존재성 ‘NULL ✕’.

17. 주식별자가 되려면 네 가지 특징을 갖춰야 합니다.
18. 첫째는 유일성으로, 주문번호 하나가 주문 딱 한 건만 가리켜야 합니다.
19. 둘째는 최소성으로, 주문번호만으로 구분되는데 주문일자까지 덧붙이면 안 됩니다.
20. 셋째는 불변성으로, 한 번 정한 주문번호는 나중에 바뀌지 않아야 합니다.
21. 넷째는 존재성으로, 주식별자에는 반드시 값이 있어야 하고 NULL이 올 수 없습니다.

## 6. 식별자의 분류
> 화면: 분류표 네 줄이 한 줄씩 — 대표성: 주식별자 고객번호 / 보조식별자 이메일 · 스스로 생성: 내부식별자 주문번호 / 외부식별자 주문의 고객번호 · 속성 수: 단일식별자 주문번호 / 복합식별자 주문번호 + 상품코드 · 대체 여부: 본질식별자 주문번호 + 상품코드 / 인조식별자 주문상품번호. 설명이 끝난 줄은 흐려진다.

22. 식별자는 네 가지 기준으로 나눕니다.
23. 대표성으로 보면, 다른 엔터티와 이어 주는 대표인 고객번호는 주식별자입니다.
24. 이메일도 고객마다 달라 구분은 되지만, 바뀔 수 있어 대표로 쓰지 않으므로 보조식별자입니다.
25. 스스로 만들었는지로 보면, 주문번호는 주문이 스스로 만든 내부식별자입니다.
26. 주문에 들어 있는 고객번호는 관계를 통해 받아 온 외부식별자로, 데이터베이스에서는 외래키 역할을 합니다.
27. 속성의 수로 보면, 주문번호는 단일식별자, 주문번호와 상품코드의 조합은 복합식별자입니다.
28. 대체 여부로 보면, 업무에서 생긴 주문번호와 상품코드는 본질식별자, 일련번호로 만든 주문상품번호는 인조식별자입니다.

## 7. 식별자 관계와 비식별자 관계
> 화면: 주문 → 주문상품 실선 — ‘주문번호’ 칩이 주문상품의 가로선 위로 내려가 앉는다, 라벨 ‘식별자 관계 · 실선 · 강한 연결’ → 고객 → 주문 점선 — ‘고객번호’ 칩이 주문의 가로선 아래로 내려가 앉는다, 라벨 ‘비식별자 관계 · 점선 · 약한 연결’.

29. 관계를 맺으면 부모 엔터티의 주식별자가 자식 엔터티로 내려옵니다.
30. 주문의 주문번호는 주문상품에서 가로선 위, 곧 주식별자의 일부가 됩니다.
31. 이런 관계가 식별자 관계이고, IE 표기법에서는 실선으로 그립니다.
32. 그래서 주문 없이는 주문상품도 생길 수 없는, 강한 연결입니다.
33. 고객의 고객번호는 주문에서 가로선 아래, 일반 속성으로 들어갑니다.
34. 이것이 비식별자 관계로, 약한 연결을 뜻하는 점선으로 그립니다.

## 8. 어느 쪽을 고를까
> 화면: 왼쪽 — 주문상품 아래 실선으로 점선 테두리의 배송 상자(주문번호 · 상품코드 · 배송순번 / 배송일자, 위에 작은 글씨 ‘둔다면’), 가로선 위가 세 칸으로 길어진다 → 오른쪽 — 고객 · 주문 · 주문상품 세 상자, 고객번호가 주문에서 멈춤 → 고객에서 주문상품까지 ‘주문을 거쳐 조인’ 화살표 → 칩 세 개 ‘연결이 약할 때 · 자식만의 식별자가 나을 때 · 부모 없이도 생길 때’.

35. 주문상품 아래에 분할 배송을 기록하는 배송 엔터티를 둔다고 해 보겠습니다.
36. 식별자 관계로 이으면 배송의 주식별자는 주문번호, 상품코드, 배송순번, 세 칸이 됩니다.
37. 이렇게 아래로 갈수록 주식별자가 길어지고, 조인 조건도 복잡해집니다.
38. 반대로 비식별자 관계에서는 부모의 주식별자가 그 아래로 더 내려가지 않습니다.
39. 고객번호가 주문에서 멈추니, 고객별 주문상품을 보려면 주문을 거쳐 조인해야 합니다.
40. 그래서 연결이 약할 때나, 자식이 독립된 식별자를 갖는 편이 나을 때 비식별자 관계를 고릅니다.
41. 부모 없이도 자식이 생길 수 있는 선택 관계일 때도 비식별자 관계입니다.
42. 비어 있을 수 있는 값은 주식별자가 될 수 없기 때문입니다.

## 9. 인조식별자의 함정
> 화면: 주문상품 표(머리 ‘주문상품 4행’, 첫 열 주문상품번호가 주식별자) — 1 · 1001 · P01 · 2 / 2 · 1001 · P02 · 1 / 3 · 1002 · P01 · 3 / 4 · 1001 · P01 · 2 → 1행과 4행의 주문번호 · 상품코드 칸이 바이올렛 ‘같은 주문 · 같은 상품’ → 주식별자를 ‘주문번호 + 상품코드’로 바꾸면 4행에 ✕, 머리 ‘4행 → 3행’ → 칩 ‘UNIQUE 제약’ → 인덱스 칩 두 개 ‘주식별자 인덱스’ + ‘UNIQUE 인덱스’.

43. 처음 질문으로 돌아가, 주문상품번호를 주식별자로 두고 네 행을 넣어 보겠습니다.
44. 그런데 첫 행과 네 번째 행은 주문번호도, 상품코드도 똑같습니다.
45. 주문상품번호가 1번과 4번으로 다르니, 데이터베이스는 이 중복을 막지 못합니다.
46. 주문번호와 상품코드가 주식별자였다면, 네 번째 행은 거부되고 세 행만 남습니다.
47. 인조식별자를 두고도 중복을 막으려면, 두 속성에 UNIQUE 제약을 따로 걸어야 합니다.
48. 그러면 주식별자 인덱스에 더해 UNIQUE 인덱스까지 생겨, 저장 공간과 입력, 수정 부담이 커집니다.
49. 그래서 인조식별자는 본질식별자가 너무 복잡할 때처럼 꼭 필요한 경우에만 사용합니다.

## 10. 시험장 체크
> 화면: 체크 카드 세 장이 차례로 → 마지막에 작은 카드 두 줄 ‘존재에 의한 관계: 소속 자체로(부서–사원)’ / ‘행위에 의한 관계: 행위로 생김(고객–주문)’.

50. 시험장에서 챙길 것 세 가지입니다.
51. 첫째, 주식별자의 특징은 유일성, 최소성, 불변성, 존재성, 네 가지입니다.
52. 둘째, 부모의 주식별자가 자식의 주식별자로 가면 식별자 관계로 실선, 일반 속성으로 가면 비식별자 관계로 점선입니다.
53. 셋째, 인조식별자는 단순하지만, 중복 데이터가 생길 수 있고 인덱스가 늘어납니다.
54. 덧붙여, 부서와 사원처럼 소속 자체로 맺어지는 관계는 존재에 의한 관계입니다.
55. 고객과 주문처럼 주문이라는 행위로 생기는 관계는 행위에 의한 관계입니다.
