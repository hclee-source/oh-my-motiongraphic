예시 숫자(검수용): (SQL 안의 ' '는 오라클 문자열 표기, 강조 따옴표 아님. 모두 verify_examples.py에서 파이썬 re·sqlite3로 재계산)
  코드 표 6행: A101, 205, B30, 4096, 77C, 310
  REGEXP_LIKE(코드, '[0-9]{3}') → 4행(A101은 101, 4096은 409가 맞음 · 205 · 310) / B30, 77C는 숫자 두 개뿐이라 빠짐
  '^[0-9]{3}' → 3행(205, 4096, 310, A101 빠짐) / '^[0-9]{3}$' → 2행(205, 310, 4096 빠짐)
  REGEXP_LIKE(코드, '^b') → 0행 / REGEXP_LIKE(코드, '^b', 'i') → 1행(B30). 기본은 대소문자 구분(NLS_SORT 기본값 BINARY 기준)
  REGEXP_SUBSTR('2026년 11월 5일', '[0-9]+') → '2026' / (…, '[0-9]+', 1, 2) → '11' / (…, '[0-9]{5}') → NULL
  REGEXP_REPLACE('010-1234-5678', '[0-9]{4}$', '****') → '010-1234-****' / '[0-9]{4}' → '010-****-****'(맞는 부분 모두, 010은 숫자 세 개라 안 맞음)
  REGEXP_REPLACE('010-1234-5678', '[^0-9]') → '01012345678'(바꿀 문자 생략 = 맞는 부분 삭제, 숫자 11개)
  REGEXP_COUNT('banana', 'a') → 3 / REGEXP_COUNT('banana', 'ana') → 1(2~4번째 글자에서 맞춘 뒤 5번째부터 다시 찾음, 겹쳐 세지 않음)
  REGEXP_INSTR('banana', 'n') → 3(처음 맞는 곳의 시작 위치) / 맞는 곳 없으면 REGEXP_INSTR·REGEXP_COUNT 0, REGEXP_SUBSTR NULL
  REGEXP_SUBSTR('<b>굵게</b>', '<.*>') → '<b>굵게</b>'(전체, 가장 길게) / '<.*?>' → '<b>' / REGEXP_REPLACE('<b>굵게</b>', '<.*?>') → '굵게'
  기호: . 아무 글자 하나(기본 설정에서 줄바꿈 제외) / [ ] 안의 글자 중 하나 / [0-9] = \d 숫자 하나 / [^0-9] 숫자가 아닌 글자 하나 / * 0번 이상 / + 한 번 이상 / ? 없거나 한 번 / {n} 정확히 n번 / {n,m} n~m번 / ^ 시작 / $ 끝 / 반복 기호 뒤 ? = 가장 짧게
  반복 기호는 바로 앞 한 덩어리(글자 하나 또는 대괄호 하나)에 붙음: [0-9]{3} = 숫자 세 개 / 휴대폰 번호 패턴: [0-9]{3}-[0-9]{4}-[0-9]{4} / ab+ = b만 반복(ab, abb …) / (ab)+ = ab 반복(ab, abab …)

## 1. 숫자 세 자리 코드
> 화면: 코드 표 6행(A101 · 205 · B30 · 4096 · 77C · 310) → SQL 카드 WHERE REGEXP_LIKE(코드, '[0-9]{3}') → ‘몇 행?’ → 205 · 310 두 행에 ‘2행?’ 카드 → ✕ → ‘4행’.

1. 상품 코드 여섯 개 가운데, 숫자 세 자리로 된 코드만 찾으려고 합니다.
2. 그래서 ‘숫자 세 개’라는 정규 표현식을 REGEXP_LIKE 조건으로 걸었습니다.
3. 숫자 세 자리 코드는 205와 310이니, 두 행이 나올 것 같습니다.
4. 그런데 실제로는 4행이 나옵니다.
5. 오늘은 정규 표현식 함수 다섯 개를 결과 맞히기로 정리하면서, 이 4행의 이유도 찾아보겠습니다.

## 2. 정규 표현식과 함수 다섯 개
> 화면: LIKE 카드(% 0개 이상 아무 글자 · _ 아무 글자 하나) 옆에 정규 표현식 카드(글자 종류 · 반복 횟수) → 함수 칩 다섯 개가 차례로: REGEXP_LIKE 조건 · REGEXP_SUBSTR 뽑기 · REGEXP_REPLACE 바꾸기 · REGEXP_INSTR 위치 · REGEXP_COUNT 개수.

6. 정규 표현식은 ‘숫자 네 개’, ‘대문자로 시작’처럼 문자열의 모양을 기호로 적는 방법입니다.
7. LIKE의 퍼센트와 밑줄보다 훨씬 자세하게, 글자의 종류와 반복 횟수까지 적을 수 있습니다.
8. 오라클의 정규 표현식 함수는 다섯 개로, 조건을 거는 REGEXP_LIKE, 뽑는 REGEXP_SUBSTR, 바꾸는 REGEXP_REPLACE가 기본입니다.
9. 여기에 위치를 알려 주는 REGEXP_INSTR, 개수를 세는 REGEXP_COUNT가 더해집니다.

## 3. 글자 하나를 뜻하는 기호
> 화면: 기호 카드 네 줄이 차례로 — . 아무 글자 하나 / [ ] 안에 적은 글자 중 하나 / [0-9] · \d 숫자 하나 / [^0-9] 숫자가 아닌 글자 하나.

10. 먼저 글자 하나를 뜻하는 기호입니다.
11. 점은 아무 글자나 하나, 대괄호는 그 안에 적은 글자 가운데 하나를 뜻합니다.
12. 대괄호 안에 0부터 9까지 범위를 적으면 숫자 하나를 뜻하고, 역슬래시 d도 같은 뜻입니다.
13. 대괄호 안 맨 앞에 캐럿을 붙이면 반대로 적은 글자가 아닌 글자 하나가 되는데, 대괄호 밖의 캐럿과는 뜻이 다릅니다.

## 4. 반복 횟수를 뜻하는 기호
> 화면: 기호 카드 — * 0번 이상 / + 한 번 이상 / ? 없거나 한 번 / {n} 정확히 n번 · {n,m} n번에서 m번 → 아래에 휴대폰 번호 패턴 [0-9]{3}-[0-9]{4}-[0-9]{4} → ab+ (b만 반복) 와 (ab)+ (ab 반복) 비교.

14. 다음은 바로 앞 덩어리가 몇 번 나오는지를 정하는 기호입니다.
15. 별표는 0번 이상, 더하기 기호는 한 번 이상, 물음표는 없거나 한 번입니다.
16. 중괄호에 숫자 하나를 적으면 정확히 그 횟수만큼, 숫자 두 개를 쉼표로 적으면 그 범위만큼 반복합니다.
17. 그래서 휴대폰 번호는 숫자 세 개, 하이픈, 숫자 네 개, 하이픈, 숫자 네 개로 적을 수 있습니다.
18. 반복 기호는 바로 앞 한 덩어리, 곧 글자 하나나 대괄호 하나에만 붙으니, 여러 글자를 반복하려면 괄호로 묶습니다.

## 5. REGEXP_LIKE와 캐럿 · 달러 기호
> 화면: 왼쪽 SQL 카드 WHERE REGEXP_LIKE(코드, '[0-9]{3}'), 오른쪽 코드 표 6행 → 한 행씩 판정(A101의 101 · 4096의 409에 밑줄, B30 · 77C 흐려짐) → 표 머리 4행 → 패턴 앞에 ^ → A101 흐려져 3행 → 뒤에 $ → 4096 흐려져 2행 → 아래 작은 카드 REGEXP_LIKE(코드, '^b') 0행 / REGEXP_LIKE(코드, '^b', 'i') 1행(B30).

19. 이제 처음 문제로 돌아가 보겠습니다.
20. REGEXP_LIKE는 패턴이 문자열의 어느 한 부분에서라도 맞으면 참입니다.
21. A101은 뒤쪽 101이, 4096은 앞쪽 409가 숫자 세 개라서 참이 됩니다.
22. 숫자가 두 개뿐인 B30과 77C만 빠지고, 4행이 나옵니다.
23. 패턴 맨 앞에 시작을 뜻하는 캐럿을 붙이면, 숫자로 시작하지 않는 A101이 빠져 3행입니다.
24. 맨 뒤에 끝을 뜻하는 달러 기호까지 붙이면, 네 자리인 4096도 빠지고 205와 310, 두 행이 남습니다.
25. 문자열 전체를 맞춰야 하는 LIKE와 달리, 정규 표현식은 캐럿과 달러 기호로 시작과 끝을 직접 묶어야 합니다.
26. 또 정규 표현식은 기본 설정에서 대소문자를 구분합니다.
27. 소문자 b로 시작하는 코드를 찾으면 0행입니다.
28. 옵션 ‘i’를 주면 대소문자를 가리지 않아서, 대문자 B로 시작하는 B30이 나와 1행이 됩니다.

## 6. REGEXP_SUBSTR
> 화면: 문자열 칩 ‘2026년 11월 5일’ → REGEXP_SUBSTR(…, '[0-9]+') = ? → 2026 · 11 · 5 세 덩어리에 테두리, 첫 덩어리 2026이 밝아짐 → 인자 1, 2 추가(시작 위치 · 몇 번째) → 11 → 패턴 '[0-9]{5}' → NULL.

29. 여기서부터는 결과 맞히기입니다.
30. ‘2026년 11월 5일’에서 숫자가 한 번 이상 이어진 부분을 REGEXP_SUBSTR으로 뽑으면 무엇이 나올까요?
31. 답은 2026입니다.
32. 이어진 숫자를 한 덩어리로 잡고, 여러 덩어리 가운데 첫 번째 하나만 돌려줍니다.
33. 세 번째 인자는 찾기 시작할 위치, 네 번째 인자는 몇 번째 덩어리인지를 정합니다.
34. 그래서 시작 위치에 1을, 몇 번째에 2를 주면 두 번째 덩어리인 11이 나옵니다.
35. 숫자 다섯 개처럼 맞는 부분이 없으면 결과는 NULL입니다.

## 7. REGEXP_REPLACE
> 화면: 문자열 칩 ‘010-1234-5678’ → REGEXP_REPLACE(…, '[0-9]{4}$', '****') → 010-1234-**** → 패턴에서 $를 지움 → ‘?’ → 010-****-**** → REGEXP_REPLACE(…, '[^0-9]') → 01012345678 (숫자 11개).

36. REGEXP_REPLACE로 전화번호 끝의 숫자 네 개를 별 네 개로 바꾸면, 마지막 네 자리가 가려집니다.
37. 그렇다면 끝을 뜻하는 달러 기호를 빼면 어떻게 될까요?
38. 그러면 가운데 네 자리도 가려집니다.
39. REGEXP_REPLACE는 따로 정하지 않으면, 맞는 부분을 하나만이 아니라 모두 바꾸기 때문입니다.
40. 바꿀 문자를 아예 적지 않으면 맞는 부분이 지워져서, 숫자가 아닌 글자를 지우면 숫자 열한 개만 남습니다.

## 8. REGEXP_COUNT와 REGEXP_INSTR
> 화면: 글자 칩 여섯 칸 b · a · n · a · n · a → 'a' 세 칸 밝아짐 → 3 → 'ana' 2~4번째 칸 묶음, 4~6번째 묶음은 겹쳐서 ✕ → 1 → REGEXP_INSTR 'n' 세 번째 칸 → 3 → 아래 한 줄 ‘없으면 REGEXP_INSTR · REGEXP_COUNT 0, REGEXP_SUBSTR NULL’.

41. REGEXP_COUNT로 ‘banana’에서 알파벳 a를 세면 3입니다.
42. 그럼 세 글자 ana를 세면 몇 개일까요?
43. 겹치게 세면 두 번이지만, 답은 1입니다.
44. 한 번 맞춘 글자는 건너뛰고, 그 뒤에서부터 이어서 찾기 때문입니다.
45. REGEXP_INSTR은 처음 맞는 곳의 시작 위치를 돌려주는데, 알파벳 n은 세 번째 글자라서 3입니다.
46. 맞는 곳이 없으면 REGEXP_INSTR과 REGEXP_COUNT는 0을, REGEXP_SUBSTR은 NULL을 돌려줍니다.

## 9. 가장 길게 잡는 반복
> 화면: 문자열 칩 ‘<b>굵게</b>’ → REGEXP_SUBSTR(…, '<.*>') → ‘<b>’ 카드에 ✕, 문자열 전체가 밝아짐 → 패턴 '<.*?>' → 앞의 ‘<b>’만 → REGEXP_REPLACE(…, '<.*?>') → 굵게.

47. 마지막으로, 태그를 뽑으려고 여는 꺾쇠괄호 뒤에 점과 별표를 적고 닫는 꺾쇠괄호로 끝냈습니다.
48. 결과는 앞의 태그 하나일까요?
49. 답은 문자열 전체입니다.
50. 반복 기호는 맞출 수 있는 가장 긴 부분을 잡아서, 맨 마지막 닫는 꺾쇠괄호까지 가져갑니다.
51. 반복 기호 뒤에 물음표를 붙이면 가장 짧게 잡아서, 앞의 태그 하나만 나옵니다.
52. 이 패턴으로 REGEXP_REPLACE를 하면 태그만 모두 지워져 ‘굵게’라는 글자만 남습니다.

## 10. 시험장 체크
> 화면: 체크 카드 세 장이 차례로 → 마지막에 작은 카드 ‘대괄호 안 맨 앞의 ^ = 아닌 것’.

53. 시험장에서 챙길 것 세 가지입니다.
54. 첫째, 캐럿과 달러 기호가 없으면 패턴이 문자열 일부에만 맞아도 참입니다.
55. 둘째, REGEXP_SUBSTR은 첫 번째로 맞는 부분 하나를 뽑고, REGEXP_REPLACE는 맞는 부분을 모두 바꿉니다.
56. 셋째, 반복 기호는 가장 길게 맞추고, 뒤에 물음표를 붙여야 가장 짧게 맞춥니다.
57. 덧붙여, 대괄호 안 맨 앞의 캐럿은 시작이 아니라 ‘이 글자가 아닌 것’이라는 뜻입니다.

## 11. 한 줄 정리
> 화면: 두 줄 정리 — ‘일부만 맞아도 참 → ^ · $’ / ‘가장 길게 → ?’.

58. 오늘 내용을 한 줄로 정리하면 이렇습니다.
59. 정규 표현식은 일부만 맞아도 참이고, 가장 길게 잡습니다.
60. 전체를 맞추려면 캐럿과 달러 기호를, 짧게 잡으려면 물음표를 붙입니다.
