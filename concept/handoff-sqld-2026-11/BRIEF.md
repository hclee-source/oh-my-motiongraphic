## Phase 1 — script only (then STOP and report)

Write `script.md` (main, 16:9) and `shorts/script.md` (9:16) in your folder, in exactly the same format as 007:
- Front matter between `---` lines: 번호, 개념 (with ‘(SQLD n과목 …)’), 시험: SQLD, 제목 후보 (2–3, like 007: hook-style, ending ‘| SQLD’), 썸네일 문구 (윗줄 ~9자 / 오해 한 마디 ~4자 with ‘?’ / 띠 ~14자 — the 함정 경고형 thumbnail: a common misconception crossed out), 예시 숫자(검수용) (ALL example data and every expected result, so a reviewer can recompute), 상태: 대본 (2026-11-05).
- Chapters `## n. 제목`, each with a `> 화면:` line describing the visual (concrete: what card/table/chips appear and change), then numbered narration sentences continuing across chapters.
- Main: aim ≈4–5 min (≈48–58 sentences). Don't pad: if the topic is naturally smaller, ~3.5 min is fine. Structure like 007: hook question (a concrete trap) → one small table/example walked through step by step with row counts → why → ‘시험장 체크’ (3 items + maybe one extra) → ‘한 줄 정리’. No ‘next episode’ teaser, no exam names in narration/screen (front matter/titles are fine), no episode numbers on screen.
- Shorts: ~45–65 s (≈7–12 sentences), a fresh summary — must NOT reuse the main episode's worked example/numbers (use an abstract or different tiny example). Front matter: 종류, 제목 후보, 위 고정 제목 (short topic name shown all the time), 상태. Mark caption breaks with ‘|’ inside sentences (short pieces, never split a word group).
- Oracle syntax/behaviour is the answer standard; SQL Server differences only as one short line where the exam likes to ask.
- Style: ‘~입니다’체, each sentence readable aloud in one breath; emphasis/quotes ONLY with ‘ ’ (never " " or “ ”). Particles after English keywords follow pronunciation (SELECT가, HAVING은, ROWNUM은, CONNECT BY는…). After a closing parenthesis the particle follows the last word inside it.
- Never use the character `|` in main-script narration or anywhere except as a shorts caption break (it is the caption-split marker in both). Avoid `||`.
- Known AI-voice defects (from `concept/tools/say_auto.py` header): a lone one-syllable item between commas gets dropped (write ‘1번, 2번’ or attach a unit/ending); ‘1번’ may be read as ‘한 번’ (tool fixes); ‘~에 씁니다/쓰면’ sounds like ‘했습니다’ → use ‘적습니다’, ‘~에서 쓰면’.
- Numbers on screen lines must equal the narration. Every count/sum/result must be recomputed. **Verify SQL results by actually running them** where possible: Python's built-in `sqlite3` supports window functions (incl. ROWS/RANGE frames, LAG/LEAD, NTILE, PERCENT_RANK, CUME_DIST), set operators (EXCEPT for MINUS), subqueries, recursive CTEs (to emulate CONNECT BY ordering), CASE (to emulate PIVOT). Python `re` for regex examples. For Oracle-only behaviour (ROWNUM, CONNECT BY specifics, TCL/DDL auto-commit, function edge cases) reason carefully from Oracle docs knowledge and state the rule in 예시 숫자 so the reviewer can check it. Put your verification script(s) in your episode folder as `verify_examples.py` (kept, not shown on screen).
- Keep the example tiny (5–8 rows) so every row fits on screen at readable size.

Phase 1 report (short, no file dumps): file paths, chapter list with sentence counts, estimated main length (Korean ≈ 6.5 syllables/s plus pauses), the example data in one line, anything you were unsure about (Oracle edge cases). Then end your turn and wait — the coordinator will message you with review results.

3. 4. Scenes (main + shorts) and both `build.json` files, following 007's patterns exactly:
   - Each scene is an HTML `<template>` with `#root data-composition-id="<id>"` and `data-composition-variables` (cues, dur, exit, motion-scale, plus `extra` ids). `cues` = start times of that scene's sentences (local 0-based order). Same helpers as 007 (ft/fade/stamp/head/hi). Register `window.__timelines["<id>"]`. Exit fade at D-0.4 unless `exit: false` (last scene).
   - build.json maps scenes to chapters (`"chapter": n` or a list for one continuous scene when the same table/visual continues, like 007's s03) and lists sfx `[name, local sentence index or null, offset s]`; `extra: {"x": {"sentence": N, "at": "낱말"}}` = time a word is spoken. Shorts build.json needs the `format` and `overlays` blocks exactly as in 007's shorts build.json.
   - Shared CSS (`video/assets/scene.css`, already in your folder) includes the SQL classes at the end: dark SQL card `.x-dark.q-code` with lines `.q-ln`, keyword `.q-k`, line highlight `.q-hi`, step badge `.q-no`; result table `.x-card.q-tb` with `.q-th` header and absolutely positioned rows `.q-tr`; chips `.q-chip` + `.q-ok` (violet) / `.q-ng` (dark). Grey NULL text `.q-null` (#8A8A93). You may add episode-specific CSS inside your composition files.
   - Main canvas 1920×1080: header `.x-head` at top 120, content y≈262–846, captions at the bottom (keep content above ~860). Shorts 1080×1920: content y 300–1250 only; nothing in y<140 or >1450; nothing right of x 960 below y 1000; captions y≈1300–1380.

Main motion-scale 1.6, shorts 1.0. Follow each chapter's ‘> 화면:’ line. Keep every number on screen identical to the narration and readable (no tiny text; ≥ 32px main, larger in shorts).
   - Pitfalls learned: text on a card must be a child of that card (else the checker flags ‘text over another card’); a later `fromTo` on the same property needs `immediateRender:false`; don't mix CSS transform with GSAP set on the same element; use getTotalLength not pathLength; draw ✕ marks as two thin bars, not a glyph.
5. Checks (gate before render): `.venv/Scripts/python.exe tools/heavy.py bash concept/tools/check_episode.sh concept/episodes/<ep>` — builds main+shorts, runs `hyperframes check` and the layout checker. Requirement: **‘확실’ 0건** in main and shorts and hyperframes check passes. Checker rules: cards = elements with class x-card, x-dark or x-side; it flags text overlapping text; text closer than max(10px, ¼ font size) to other text (except same-line fragments); text inside a card closer than 16px to its edge or spilling out; text within 16px of another card; card overlapping card; text-less shapes partially overlapping text (a shape must fully wrap text, like `.q-hi` behind a line, or not touch it); intended crossfades/swaps in the same spot → wrap in an element with `data-layout-allow-overlap`. ‘확실’ = both ≥0.6 opacity for ≥0.4 s; brief ‘잠깐’ transition overlaps are OK.

Align visuals to real speech: `.venv/Scripts/python.exe tools/heavy.py .venv/Scripts/python.exe concept/tools/verify_episode.py --no-pops --write-times concept/episodes/<ep>` (and the same for `concept/episodes/<ep>/shorts`) → writes word_times.json; words it can't find go in `word_times.manual.json`. If a scene stamps items one by one on spoken numbers, use the real times from `listen/words.json` (no estimating from character counts). Then re-run the check (step 5) — still 확실 0.
