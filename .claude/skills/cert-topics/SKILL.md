# 소재 목록 (제작 체계 1번 역할)

먼저 `concept/RULES.md`(채널 규칙)를 읽는다. 개념 영상 작업은 `C:\hcl\oh-my-motiongraphic\concept\`에 있다(2026-10-30 `C:\hcl\cert-channel`에서 옮김). 아래 파일 경로는 `concept/` 기준이다. 이 역할은 **무엇을 만들지**만 정한다. 대본은 2번 역할, 검수는 3번 역할이 맡는다.

## 파일
- `topics/blueprint.json` — 공식 출제기준(데이터자격검정 원문을 옮긴 것). 번호 체계: ADsP는 과목.주요항목.세부항목, 빅분기는 과목.주요항목.세부항목.세세항목.
- `topics/topics.json` — 개념 목록. 한 개념 = 한 편. 칸: order(만들 순서), id, title, group(묶음), adsp·bigdata(출제기준 번호, 둘 다 있으면 공통), calc(계산 문제로 만들기 좋음), prereq(먼저 나와야 할 id), cover(다룰 핵심), status, folder.
- `topics/진행표.md` — 사람이 보는 표. 자동으로 만들어진다.
- `tools/topics.py` — 아래 명령.

## 명령 (저장소 맨 위 폴더에서 `.venv/Scripts/python.exe concept/tools/topics.py ...`)
- `next [개수]` — 다음에 만들 주제. 선수 개념이 아직 대기면 함께 알려 준다.
- `set <id> <상태> [편 폴더]` — 상태: 대기 → 대본 → 검수 통과 → 영상 완성 → 업로드 완료. 대본을 시작할 때 `대본`과 편 폴더(예: `episodes/002-roc-auc`)를 같이 적는다.
- `check` — 번호·선수 개념·중복 검사와 출제기준 빈 곳 찾기. 목록을 손으로 고친 뒤 반드시 돌린다(진행표도 다시 만든다).

## 다음 주제 고르기
1. 기본은 `next`가 주는 순서를 따른다. 순서 원칙:
   - 두 시험 공통 개념이 먼저.
   - 같은 묶음(모델 평가 → 연관분석 → 군집 → 기술통계 → 확률과 분포 → 추정과 검정 → 상관과 회귀 → 분류 모델 → 전처리 → 차원 축소 → 시계열 → 데이터 이해·분석 기획)은 이어서 낸다.
   - 그다음 ADsP만, 빅분기만 나오는 개념.
2. 시험이 6주 안으로 다가오면 그 시험에서 비중이 큰 개념을 앞으로 당겨도 된다. 당길 때는 사용자에게 한 줄로 알리고 topics.json의 order를 바꾼 뒤 `check`를 돌린다.
3. 편 폴더 이름은 `episodes/<세 자리 번호>-<id>`. 번호는 만든 순서다(화면에는 번호를 넣지 않는다).

## 목록 고치기
- 새 개념은 출제기준 번호가 있어야 넣는다. 출제기준 밖의 내용은 넣지 않는다.
- 너무 큰 개념은 두 편으로 나누고, 너무 작은 개념은 이웃 개념과 합친다(한 편 4~6분 기준).
- 출제기준이 바뀌면(빅분기 현재 적용 기간 2024~2026년, 2027년 새 기준 확인 필요):
  1. 공식 페이지(blueprint.json의 source)에서 표를 다시 받는다.
  2. blueprint.json을 고친다.
  3. `check`로 없어진 번호와 빈 곳을 찾는다.
  4. 목록을 고친다.
  5. 바뀐 점을 사용자에게 쉬운 말로 알린다.

## 보고
사용자는 개발자가 아니다. 쉬운 우리말로, 영어 개발 용어 없이 알린다. 예: ‘다음은 2번 ‘민감도·특이도와 ROC 곡선’입니다(두 시험 공통, 계산 문제 단골).’
